### 2. Архитектура интеграции

В боевой шаблон `templates/sandbox/student_schedule.html` интегрированы утверждённые компоненты Concept D:

1. **Top Masthead & Недельный степпер:**
   - Канонический бейдж: `ЛИЧНЫЙ МАРШРУТ` и заголовок `Моё расписание`.
   - Контекст недели: динамическая метка (`unified-week-label`), количество запланированных уроков и дедлайнов ДЗ.
   - Степпер навигации по неделям: кнопки «Пред.», «Сегодня», «След.» (`navigateWeek(-1)`, `navigateToday()`, `navigateWeek(1)`).
2. **7-дневная эргономичная лента (Unified 7-Day Ribbon):**
   - Расположена в контейнере `#unified-ribbon-track` с тонкой одинарной границей (`border-slate-200/80`).
   - Каждая вкладка (`.unified-day-tab`) отображает: краткое название дня (`Пн`, `Вт`...), индикатор «Сегодня» (зеленая точка), число месяца, аккуратный индикатор нагрузки (точка + количество событий или счетчик `+N` для мульти-событий, либо метку `Отдых`).
   - Реактивное переключение без перезагрузки: клик по вкладке моментально переключает контекст активного дня через JS (`handleUnifiedSelectDay(dayIndex)`).
3. **Рабочая область выбранного дня (Active Day Workspace):**
   - Заголовок дня (`#unified-day-title`) с бейджем «Сегодня» при совпадении с текущей датой.
   - Деликатный совет маскота Бу (`#unified-boo-coach-tip`), адаптирующийся под фактическую нагрузку выбранного дня (скрыт на узких мобильных экранах для соблюдения чистоты первого экрана).
   - **Равноправные карточки занятий (`.peer-event-card`):**
     - Располагаются в сбалансированной 2-колоночной сетке (`grid-cols-1 lg:grid-cols-2`).
     - Тематический бейдж предмета («Информатика»), время занятия, бейдж статуса («Занятие», «Проведено», «Идёт урок»).
     - Тема урока с переносом длинных слов (`hyphens-auto break-words`).
     - Блок преподавателя с аватаром и ролью.
     - **Первичная кнопка действия `btn-3d-primary` («Войти в урок →») расположена непосредственно под строкой преподавателя** над материалами — гарантированная видимость на первом экране.
     - Заметки преподавателя к конкретному занятию («Совет преподавателя: ...»).
     - Контекстные материалы и конспекты к уроку.
   - **Компактные полосы домашних заданий:**
     - Горизонтальные карточки с желто-янтарным акцентом, не раздувающие высоту дня.
     - Дедлайн («До 23:59»), название задания, описание количества задач и кнопка сдачи работы `btn-3d-amber` («Сдать работу →» или «Продолжить выполнение →»).
   - **Органический Empty State с Бу:**
     - Если в выбранный день нет занятий, отображается дружелюбный 3D-маскот Бу с мотивирующим текстом и быстрыми ссылками на банк задач и базу знаний.
4. **Нижняя полоса недельного ритма и заметок (`#weekly-insights-bar`):**
   - Общий персональный совет репетитора на неделю (`#unified-general-notes`).
   - Сводка прогресса недели: количество запланированных уроков, сданных ДЗ, процент прохождения недели и индикатор ударного темпа.

### 3. Модель данных и источники правды

Интеграция работает исключительно на действительных данных BooStudy, исключая любые статические моки:

| Компонент интерфейса | Источник данных в бэкенде (`app/schedule/routes.py`) | Связанные модели БД |
| :--- | :--- | :--- |
| **Сетка 7 дней недели** | `schedule_page_data['weekdays']` | Вычисление диапазона недели на основе часового пояса ученика (`display_tz`) |
| **Занятия ученика** | `schedule_page_data['lessons']` и `weekdays[i]['events']` (тип `lesson`) | `Lesson` (фильтрация по `student_id`, статусам `planned`, `completed`, `cancelled`) |
| **Домашние задания** | `schedule_page_data['active_homework']` и `weekdays[i]['events']` (тип `homework`) | `Submission`, `Assignment` (фильтрация по `student_id`, статусам `ASSIGNED`, `IN_PROGRESS`, `RETURNED`, `SUBMITTED`, дедупликация по `assignment_id`) |
| **Преподаватель** | `schedule_page_data['teacher_name']`, `teacher_avatar` | Резолв через `Student.mentor_id` -> `User`, fallback через `Enrollment.tutor_id` -> `User`, безопасный фолбек `Преподаватель курса` |
| **Полезные материалы** | `schedule_page_data['useful_materials']` | `Lesson.materials` + генерация ссылок на конспекты тем через `url_for('theory.theory_index')` |
| **Заметки преподавателя** | `schedule_page_data['student_notes_general']` | Последняя заполненная запись из `Lesson.student_notes` или `Lesson.notes` |
| **Метрики и статистика** | `schedule_page_data['weekly_stats']` | Агрегация: проведенные уроки, запланированные уроки, ДЗ, процент завершения |

### 4. Решение проблемы Multi-Teacher

#### Текущее состояние в Sprint 2.0:
- В текущей схеме базы данных BooStudy модель `Lesson` связывается с учеником через поле `student_id`, но не содержит прямого внешнего ключа `teacher_id` (преподаватель исторически закрепляется за учеником через профиль `Student.mentor_id` либо через связку `Enrollment.tutor_id`).
- В соответствии с условиями Sprint 2.0, **никакие миграции базы данных или изменения модели `Lesson` в этом спринте не проводились**.
- Реализован надёжный многоуровневый алгоритм определения преподавателя:
  1. Проверка `Student.mentor_id` и получение имени и аватара ментора из таблицы `User`.
  2. Если ментор не назначен — поиск тьютора через активный `Enrollment` ученика.
  3. Если связь отсутствует — отображение нейтрального системного обозначения:
     `teacher_name = 'Преподаватель курса'`, `teacher_avatar = '/static/images/schedule/mock_teacher_avatar.png'`.
- Алгоритм защищён от вымышленных фамилий и гарантирует нейтральное корректное отображение.

#### Архитектурная дорожная карта поддержки нескольких преподавателей (Sprint 2.1+):
1. **Схема данных (Database Migration):**
   - Добавление nullable-поля `teacher_id = Column(Integer, ForeignKey('users.id'), nullable=True)` в модель `Lesson`.
   - Создание обратимой Alembic-миграции с data-backfill скриптом (заполнение `teacher_id` из `Student.mentor_id` для существующих уроков).
2. **Tutor Core & API Contract:**
   - Обновление эндпоинтов бронирования и расписания в модулях `app/schedule/routes.py` и `app/lessons/routes.py` с явной передачей `teacher_id`.
   - Добавление фильтрации занятий по преподавателю для учеников, обучающихся у нескольких репетиторов одновременно (например, профильная математика + информатика).
3. **Frontend UI Adaptation:**
   - В равноправных карточках Concept D блок преподавателя уже спроектирован контекстным для каждого занятия (`ev.teacher`), что позволит без изменения верстки отображать разных преподавателей для параллельных предметов в один и тот же день.

### 5. Обратная совместимость и безопасность

1. **Защита контракта данных:**
   - Сохранён канонический тег `<script type="application/json" id="schedule-data">{{ schedule_page_data | tojson }}</script>`.
   - Шаблон устойчив к пустым данным (`test_student_schedule_undefined_defense`): использование безопасных фильтров Jinja2 `sp_data|default({}, true)`, `weekdays_list|default([], true)`.
2. **Скрытые якорные элементы для существующих тестов:**
   - Сохранены элементы `<div id="svg-stations-container" style="display:none"></div>` и `<div id="hero-focus-card" style="display:none"></div>`.
   - Сохранены селекторы `#hero-main-title`, `#hero-description`, `#hero-time-badge`, `#useful-materials-items`, `#tutor-note-card` в скрытом служебном блоке, что предотвращает поломку устаревших тестов при полном переходе на новую DOM-структуру.
3. **RBAC и изоляция данных:**
   - Ученик видит строго свои уроки и свои домашние задания. Занятия и ДЗ других учеников изолированы на уровне SQL-запросов (`filter_by(student_id=st_obj.student_id)`). Проверено тестом `test_student_schedule_real_lesson_and_rbac`.
4. **Неприкосновенность подсистем:**
   - Модули Tutor Core, финансового биллинга, Telegram-уведомлений и production-конфигурации не модифицировались.
