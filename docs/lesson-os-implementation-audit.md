# BooStudy OS 2.0 — карта действующей комнаты

Этот документ фиксирует архитектуру маршрута `/lesson/<id>/room` перед дальнейшей визуальной и функциональной доводкой.

## Компоненты и источники данных

| Компонент | Текущая реализация | Данные и поведение |
| --- | --- | --- |
| Маршрут и доступ | `app/lessons/routes.py:lesson_interactive_room` | Урок, ученик, права, задания, материалы курса, состояние Studio |
| Экран комнаты | `templates/sandbox/trainer.html` в режиме `room_mode` | Код, окна, док, доска, конспекты, терминал |
| Оконный менеджер | `OSWindowManager` в `trainer.html` | Focus/z-index, drag, resize, границы, локальное расположение по уроку и пользователю |
| Объектная доска | `canvas-window` и логика в `trainer.html` | Страницы, объекты, штрихи, zoom, undo/redo, импорт/экспорт |
| Хранение доски | `app/lessons/whiteboard_service.py` | Snapshot и журнал операций в модели доски |
| Совместная работа | `app/lessons/lesson_socket.py`, клиентские обработчики комнаты | Presence, операции доски, курсоры, код, проведение урока |
| Редактор Python | `code-editor-textarea`, virtualFS и подсветка в `trainer.html` | Синхронизируемый код и запуск Skulpt |
| Терминал | `terminal-window` в `trainer.html` | Реальный вывод и ошибки Python, интерактивный input |
| Теория | Выборка опубликованных блоков в маршруте, `theory-window` | HTML теории исходного курса; ограничения доступа ученика |
| Задания | Выборка `classwork_tasks` в маршруте, `task-window` | Видимость задания/ответа, создание и назначение учителем |
| Конспекты | `notes-window`, `teacher-notes-window` | Студенческие и преподавательские записи раздельно |

## Окна и инструменты

Окна: редактор кода, условие задания, терминал, теория, информация об уроке, конспект ученика, конспект преподавателя, справочные материалы. Интерактивная доска теперь служит постоянным рабочим столом и не участвует в обычном управлении окнами.

Инструменты доски: выбор, рука, перо, маркер, ластик, текст, стикер, фигуры, стрелки, фреймы, комментарии, лазер, файлы, undo/redo, сетка, snap, масштаб, импорт/экспорт, реакции и управление проведением. Дополнительные действия остаются в системном меню доски.

## Состояния и события

- Личное: положение и размеры окон сохраняются локально с ключом `lesson_id + viewer_id`; фокус и видимость окон живут в браузере.
- Общее: документ доски и его версия живут в серверном snapshot и журнале, а код и управление занятием синхронизируются через текущие каналы урока.
- Socket.IO: `whiteboard_join/snapshot/operation/operations/ack/conflict`, live stroke/camera/laser/pointer, presence/reaction, `lesson_code_join/snapshot/update/cursor`, `lesson_room_ui/state`, события обновления заданий.
- Права: маршрут проверяет принадлежность к ученику; сервер дополнительно проверяет операции доски и управление комнатой. Теория в окне отбирается по опубликованности и ограничениям ученика.

## Риски для следующего прохода

1. Старый `trainer.html` содержит много правил тренажёра и комнаты в одном файле; при изменении layout нужны проверки обеих веток.
2. Ученик и учитель должны видеть один документ доски, но их локальные окна могут быть расположены по-разному.
3. На узком экране несколько стартовых окон закрывали бы друг друга; задача и терминал стартуют свёрнутыми, док их возвращает.
4. Существующее окно справочных материалов и панель файлов пока требуют увязки с уроковыми вложениями и доком.
5. В референсе показан насыщенный учебный холст. На пустом реальном уроке нельзя подменять его статичным рисунком.
6. Полная проверка teacher/student, reconnect, drag/resize после смены viewport и визуальное сравнение всех заданных размеров ещё требуется.
