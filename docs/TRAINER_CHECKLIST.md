# Тренажёр: что делать и что проверять

Чек-лист для доведения тренажёра до «идеала»: настройка, доработки и проверки.

---

## 1. Что уже сделано (платформа + trainer_app)

| Компонент | Статус |
|-----------|--------|
| API подсказок | **GET** `/internal/trainer/task/<task_id>/hint?level=1|2|3` — подсказка из БД (`Tasks.hints`), без ответа/решения |
| Клиент в тренажёре | `PlatformClient.get_hint(task_id, level)` в `trainer_app/platform_client.py` |
| Логика подсказок в Streamlit | При нажатии «Получить подсказку»: сначала запрос к платформе (уровни 1→2→3), при отсутствии — локальная база знаний, затем LLM |
| Проверка ответа | Ответ задания приходит в payload задачи и используется только для проверки ввода ученика; в интерфейсе ответ не показывается |
| Сессии, сохранение, история | API и вкладки в тренажёре работают |

---

## 2. Что сделать (по приоритету)

### 2.1. Обязательно

- [ ] **Переменные окружения**
  - На платформе: `TRAINER_URL` — URL Streamlit-тренажёра.
  - В тренажёре (Streamlit): `PLATFORM_BASE_URL` или `TRAINER_PLATFORM_URL` — базовый URL платформы (для вызовов API).
- [ ] **Синхронизация эталонов**  
  В удалённой админке выполнить «Синхронизировать эталоны 19–21» (и при необходимости расширить набор). От этого зависят подсказки в БД для заданий с заполненным `Tasks.hints`.
- [ ] **Проверка подсказок по уровням**  
  Убедиться, что у выбранных заданий в БД есть подсказки (поля `Tasks.hints` заполнены после синхронизации эталонов). Задания без подсказок будут использовать фоллбэк (локальные знания или LLM).

### 2.2. Желательно

- [ ] **LLM для тренажёра**  
  Если нужен фоллбэк на подсказки от модели: настроить провайдер в `trainer_app/llm/providers.py` и при необходимости ключи в окружении.
- [ ] **Локальная база знаний**  
  При необходимости добавить/обновить файлы в `trainer_knowledge/` (формат с `hint_ladder`, ключ `hint`), чтобы подсказки работали и без платформы/эталонов.

### 2.3. Опционально

- [ ] Не показывать кнопку «Получить подсказку» повторно для одного и того же уровня (или показывать «Следующая подсказка» после 1 и 2).
- [ ] При 404 от hint API показывать короткое сообщение «Подсказки для этого задания нет» перед фоллбэком на LLM.
- [ ] Вложения к заданию: если в задаче есть `attached_files`, проверить, что платформа отдаёт ссылки на файлы и тренажёр их отображает или даёт скачать.

## 3. Что проверять (ручные проверки)

### 3.1. Доступ и авторизация

| # | Действие | Ожидаемый результат |
|---|----------|----------------------|
| 1 | Открыть на платформе страницу «Тренажёр» (по роуту с iframe) | Отображается страница с iframe тренажёра или сообщение «TRAINER_URL не задан» |
| 2 | При заданном `TRAINER_URL` открыть тренажёр без токена (напрямую URL Streamlit) | Ошибка «Нет token. Открой через платформу» (или аналог) |
| 3 | Открыть тренажёр через платформу (кнопка/ссылка из интерфейса) | Iframe загружается с токеном в URL, тренажёр не пишет об отсутствии token |

### 3.2. Задания

| # | Действие | Ожидаемый результат |
|---|----------|----------------------|
| 4 | Выбрать тип задания (например, №19) и запросить задачу | Появляется текст задания (content_html), без ответа в интерфейсе |
| 5 | Ввести неверный ответ и отправить | Сообщение что ответ неверный (или аналог), ответ из БД не показывается |
| 6 | Ввести верный ответ (в том числе с нормализацией: пробелы, регистр по правилам) | Подтверждение что ответ верный |
| 7 | Нажать «Следующее задание» (или аналог) | Новое задание того же типа, без повторения предыдущего в списке «уже видел» |

### 3.3. Подсказки

| # | Действие | Ожидаемый результат |
|---|----------|----------------------|
| 8 | Нажать «Получить подсказку» первый раз | Появляется подсказка уровня 1 (из платформы, если есть в БД, иначе из локальной базы/LLM) |
| 9 | Нажать «Получить подсказку» второй и третий раз | Подсказки уровня 2 и 3 (последовательность 1→2→3), без выдачи ответа или полного решения |
| 10 | Взять задание, для которого в БД нет подсказок (нет `Tasks.hints`) | Либо сообщение об отсутствии подсказки, либо фоллбэк на LLM/локальные знания без падения |
| 11 | Проверить в логах/аналитике платформы | При запросе подсказки пишется событие (например, `trainer_hint`) с task_id и level |

### 3.4. Сессии и сохранение

| # | Действие | Ожидаемый результат |
|---|----------|----------------------|
| 12 | Написать код (или ввести ответ), нажать «Сохранить прогресс» | Сообщение «Сохранено!», при перезагрузке/возврате сессия доступна в истории |
| 13 | Открыть вкладку «История» / сохранённые попытки | Список сессий, можно открыть нужную и продолжить (если реализовано) |

### 3.5. Ограничения доступа (тарифы/роли)

| # | Действие | Ожидаемый результат |
|---|----------|----------------------|
| 14 | Войти как пользователь без доступа к тренажёру (тариф/роль без trainer) | При открытии тренажёра — отказ или редирект по правилам платформы |
| 15 | Войти как ученик с доступом к тренажёру | Тренажёр открывается, задания и подсказки работают в рамках прав |

## 4. Краткий чек-лист «до идеала»

1. Задать **TRAINER_URL** и **PLATFORM_BASE_URL** (или **TRAINER_PLATFORM_URL**).
2. Выполнить **синхронизацию эталонов** в удалённой админке.
3. Пройти пункты раздела **3** (что проверять) и убедиться, что подсказки 1→2→3 приходят с платформы там, где в БД есть `hints`.
4. Убедиться, что **ответ задания нигде не отображается**, а только используется для проверки ввода.
5. При необходимости настроить **LLM** и/или **trainer_knowledge** для фоллбэка подсказок.

После этого тренажёр считается доведённым до «идеала» в рамках текущего плана (подсказки из эталонов, без выдачи решения, с проверкой и сохранением сессий).

## 5. Настройка GigaChat (альтернатива Groq при 403)

Если Groq возвращает 403 (блокировка по региону), используйте GigaChat:

1. Получите authorization key на [developers.sber.ru](https://developers.sber.ru/docs/ru/gigachat/quickstart/main).
2. **Переменные окружения** (платформа / тренажёр):
   - `GIGACHAT_CREDENTIALS` — ключ авторизации
   - `TRAINER_LLM_PROVIDER=gigachat` — явно выбрать GigaChat (без этого приоритет: groq > gemini > gigachat)
   - `GIGACHAT_MODEL=GigaChat` — (опционально) модель по умолчанию
3. **SSL:** GigaChat использует российский корневой сертификат. На Windows/Linux:
   - Скачайте «Russian Trusted Root CA» с [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt)
   - `GIGACHAT_CA_BUNDLE_FILE` — путь к файлу сертификата
   - Для разработки: `GIGACHAT_VERIFY_SSL_CERTS=false` (не рекомендуется в проде)
4. Установите пакет: `pip install gigachat`

## 6. Диагностика 403 (Groq / GigaChat / LLM)

Реализованы средства диагностики:

1. **В тренажёре (сайдбар):** «🔧 Диагностика LLM (403)» → «Проверить ключи и тест LLM» — покажет `groq_key_set`, `gemini_key_set`, `gigachat_key_set`, результат тестового запроса к выбранному провайдеру (`test_success`, `test_response` или `test_error`).
2. **Эндпоинт:** `GET /internal/trainer/llm/diagnose?test=1` с заголовком `X-Trainer-Token: <токен>`. Токен берётся из URL тренажёра (параметр `token`).
3. **Логи платформы:** при 403 в лог пишутся `groq_key_set`, `gemini_key_set`, `gigachat_key_set`, провайдер.

**Что проверить на хостинге:**

| # | Проверка | Как |
|---|----------|-----|
| 1 | Ключ задан в окружении **платформы** (Flask/wsgi), а не только в .env тренажёра | Панель Timeweb → переменные окружения: `GROQ_API_KEY`, `GIGACHAT_CREDENTIALS` или `GEMINI_API_KEY`. |
| 2 | Процесс подхватил переменные | Перезапустить приложение после добавления ключа. Если используется gunicorn/uwsgi — перезапустить воркеры. |
| 3 | Тело ответа 403 от Groq | Вызвать diagnose?test=1 или посмотреть логи. В `test_body` будет JSON с `error.message` — причина (invalid key, model not available, region blocked и т.д.) |
| 4 | Модель доступна | `GROQ_MODEL=llama-3.1-8b-instant` — часто доступна. `llama-3.3-70b-versatile` может требовать другой тариф. |
| 5 | Блокировка по IP/региону | Запустить `curl` к `https://api.groq.com/openai/v1/chat/completions` с сервера хостинга (не с локальной машины). |
| 6 | Лимиты в Groq Console | [console.groq.com](https://console.groq.com) → Usage — не исчерпан ли дневной лимит. |
| 7 | Альтернатива Groq | `GEMINI_API_KEY` + `TRAINER_LLM_PROVIDER=gemini` или `GIGACHAT_CREDENTIALS` + `TRAINER_LLM_PROVIDER=gigachat`. |
| 8 | Без LLM | Синхронизировать эталоны в удалённой админке — подсказки из БД, Groq/GigaChat не нужен. |

## 6. Устранение типичных проблем

| Проблема | Причина | Решение |
|----------|---------|---------|
| **exec_error** при запуске кода | Исключение при выполнении или отсутствие builtin (`bin`, `hex` и т.д.). | Смотри traceback в expander. Включить runner: `TRAINER_ENABLE_RUNNER=1`. Добавлены `bin`, `hex`, `oct`, `ord`, `round` в разрешённые builtins раннера. |
| **403 groq_error / gigachat_error** при подсказке | API отклоняет запрос (ключ, лимит, регион, модель). | См. раздел 5–6 (GigaChat, Диагностика 403). |
| Поле кода без табов, подсветки | Используется `text_area` вместо редактора. | Установить `streamlit-ace`; при ошибке загрузки — fallback на text_area. |
| Запуск кода выключен | Runner отключён по умолчанию. | Задать `TRAINER_ENABLE_RUNNER=1` в окружении тренажёра. |
