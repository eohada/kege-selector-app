## 🛠️ Архитектура 0 Ошибок Линтера & JSON Data Passing

1. **Неисполняемый JSON Контейнер Данных (`type="application/json"`):**
   - Передача серверных Jinja-структур в клиентский JavaScript выполняется строго через специальный HTML-тег для JSON:
     ```html
     <script id="task-page-data" type="application/json">
     {
       "assignmentId": {{ assignment.assignment_id | tojson | safe }},
       "tasksData": {{ tasks_data | tojson | safe }},
       "messagesByTask": {{ messages_by_task | tojson | safe }}
     }
     </script>
     ```
   - В основном исполнительном блоке `<script>` данные считываются безопасным методом `JSON.parse()`:
     ```javascript
     const rawDataEl = document.getElementById('task-page-data');
     const pageData = rawDataEl ? JSON.parse(rawDataEl.textContent) : {};

     const ASSIGNMENT_ID = pageData.assignmentId;
     const TASKS_DATA = pageData.tasksData || [];
     const MESSAGES_BY_TASK = pageData.messagesByTask || {};
     ```

2. **Очистка от inline `onerror` и сырых `{{ ... }}` в `<script>`:**
   - В исполнительном `<script>` содержится **0 сырых Jinja-тегов `{{ ... }}`**, что делает синтаксис файла 100% чистым для парсеров и линтеров VS Code.
   - Все `onclick` вызовы переведены на передачу `this` и использование `dataset`: `onclick="switchTask(this)"`, `onclick="submitSingleTask(this)"`.

3. **Динамический Vendor Fallback:**
   - В случае недоступности CDN библиотека KaTeX загружается динамическим чистым JS инжектом (`loadLocalKaTeXFallback()`), без сборок сломанных inline кавычек в тегах `<link>` и `<script>`.

## 🚀 8 Ключевых Модулей Интерактивной Бизнес-Логики
- **Клиентская навигация по номерам задач:** Мгновенное переключение задач (`№ 1`, `№ 2`, `№ 3`...) без перезагрузки страницы.
- **Дифференцированные попытки:** Нажатие «Сохранить ответ» уменьшает попытки, окрашивает таб в зеленый/красный цвет. При исчерпании попыток инпут блокируется и показывается эталонный ответ.
- **Сохранение черновика и финальная сдача:** Подключены АПИ сохранения черновика и сдачи работы куратору.
- **Привязанный чат куратора:** Сообщения `AssignmentTaskChatMessage` изолированы по `assignment_id` И `task_id`.
