# Релизные сценарии BooStudy

Этот файл - маршрут для живой проверки платформы перед выпуском к настоящим ученикам, преподавателям, родителям и администраторам. Автотесты ловят падения, битые экраны и грубые визуальные ошибки, а этот список закрывает удобство, понятность и реальные пользовательские цепочки.

## 1. Быстрый автопрогон

1. Подготовить QA-аккаунты:

```bash
venv_linux/bin/python scripts/seed_release_audit.py
```

2. Запустить полный браузерный аудит:

```bash
nix-shell -p nodejs_22 --run 'npm run test:e2e:audit'
```

3. Открыть отчет:

```text
docs/qa/release_audit_report.md
```

4. Ожидаемый результат:
   - все страницы открываются с HTTP 200;
   - нет 500-ошибок;
   - нет критичных ошибок в консоли;
   - нет сломанных изображений;
   - нет горизонтального скролла;
   - есть скриншоты страниц в `test-results/release-audit/screenshots`.

5. Посмотреть прогон глазами:

```bash
nix-shell -p nodejs_22 --run 'npm run test:e2e:audit:watch'
```

## 2. Ученик

1. Войти под `qa_pool_student_1 / 123456`.
2. Открыть главную комнату ученика.
3. Проверить:
   - навигация видна и не ломается в светлой и темной теме;
   - карточки ближайших уроков, заданий, прогресса читаются;
   - кнопки ведут на ожидаемые страницы;
   - ученик не видит преподавательские и админские инструменты.

4. Открыть `Задания`.
5. Проверить:
   - список работ открывается;
   - работа с дедлайном понятно показывает статус;
   - если сдача запрещена после дедлайна, ученик видит человеческое объяснение, а не техническую ошибку;
   - если работа возвращена на доработку, редактор снова доступен.

6. Открыть одно задание внутри работы.
7. Проверить:
   - текст задания читается;
   - фамилии авторов в начале задания не отображаются;
   - картинки задания отображаются;
   - таймер стартует только после начала выполнения;
   - таймер не сбрасывается при обновлении страницы;
   - таймер не ставится на паузу при alt-tab;
   - таймер ставится на паузу только при переключении между заданиями.

8. Открыть workspace.
9. Проверить:
   - код сохраняется;
   - после обновления страницы код восстанавливается;
   - файлы открываются;
   - ученик может редактировать workspace без ошибок доступа;
   - код из совместного workspace не попадает автоматически в ответ ученика, если это не явная сдача ответа.

10. Открыть `Тренажер`.
11. Проверить:
   - старт тренировки работает;
   - ответы принимаются;
   - ошибки показываются понятно;
   - прогресс меняется ожидаемо.

12. Открыть `Теория`.
13. Проверить:
   - картинки теории отображаются;
   - страницы не показывают имена файлов вместо изображений;
   - мобильный вид не разваливается.

14. Открыть профиль ученика.
15. Проверить:
   - аватар и обложка отображаются;
   - часовой пояс понятен;
   - Telegram-статус понятен;
   - нет лишних админских полей.

## 3. Преподаватель

1. Войти под `qa_pool_tutor_1 / 123456`.
2. Открыть дашборд.
3. Проверить:
   - список учеников корректный;
   - счетчики по категориям не сбрасываются при переключении вкладок;
   - тестовые и демо-ученики отделены от обычных.

4. Открыть профиль ученика.
5. Проверить:
   - карточка ученика выглядит единообразно с остальной платформой;
   - Telegram-статус виден;
   - баланс уроков виден и редактируется;
   - при ручном изменении баланса требуется причина;
   - ученику уходит понятное уведомление об изменении баланса.

6. Создать урок из профиля ученика.
7. Проверить:
   - время сохраняется в локальном часовом поясе преподавателя;
   - у ученика урок отображается в его часовом поясе;
   - уведомление о создании урока приходит;
   - напоминание приходит вовремя.

8. Начать урок.
9. Проверить:
   - урок не завершается сразу;
   - урок завершается по указанной длительности;
   - за 120 минут списываются 2 урока, за 60 минут - 1 урок;
   - после окончания бот спрашивает заметку по ДЗ;
   - заметка не отправляется ученику;
   - заметку можно посмотреть командой в боте.

10. Открыть комнату урока.
11. Проверить:
   - преподаватель и ученик видят один workspace;
   - текст появляется у второго участника быстро;
   - удаление текста тоже синхронизируется;
   - курсоры не мешают писать;
   - участники видят присутствие друг друга.

12. Создать работу.
13. Проверить:
   - можно выбрать обычную работу и классную работу;
   - настройка MMR понятна: учитывать, не учитывать, учитывать после подтверждения;
   - быстрый пробник генерирует каждый раз новый набор;
   - картинки в заданиях видны преподавателю до выдачи.

14. Проверить работу ученика.
15. Проверить:
   - можно принять;
   - можно вернуть на доработку;
   - после возврата ученик действительно может снова работать;
   - комментарий преподавателя вызывает нужное уведомление.

## 4. Родитель

1. Войти под `qa_pool_parent_1 / 123456`.
2. Открыть родительский кабинет.
3. Проверить:
   - если ребенок привязан, он виден в кабинете;
   - если детей нет, показано понятное пустое состояние;
   - родитель не видит преподавательские и админские инструменты.

4. Открыть карточку ребенка.
5. Проверить:
   - родитель видит расписание, задания, прогресс и баланс в режиме просмотра;
   - родитель не может редактировать то, что должен менять преподаватель;
   - ссылки ведут в родительский, а не преподавательский интерфейс.

5. Открыть расписание родителя.
6. Проверить:
   - уроки ребенка отображаются;
   - время показано в часовом поясе родителя;
   - пустые состояния понятные.

## 5. Администратор и создатель

1. Войти под админа `qa_pool_admin_1 / 123456`.
2. Открыть `Пользователи`.
3. Проверить:
   - поиск работает;
   - роли видны понятно;
   - ручная привязка/отвязка Telegram доступна только тем, кому можно.

4. Открыть QA-пул.
5. Проверить:
   - можно быстро перейти к тестовым аккаунтам;
   - тестовые аккаунты не мешают обычным ученикам.

6. Открыть тарифы и подписки.
7. Проверить:
   - тариф не ломает ручное назначение уроков;
   - уроки можно назначить или обнулить даже без тарифа;
   - тариф работает как шорткат, а не как обязательное условие.

8. Открыть maintenance.
9. Проверить:
   - страница доступна только админам/создателю;
   - обычные роли туда не попадают.

## 6. Telegram

1. Привязать Telegram ученика штатным способом через код.
2. Проверить:
   - повторная привязка не дает привязать один Telegram к двум активным аккаунтам;
   - forced-команда работает только для тех, кому положено;
   - после привязки профиль на платформе показывает актуальный Telegram.

3. Создать урок.
4. Проверить уведомления:
   - создание урока;
   - напоминание за 30 минут;
   - начало урока;
   - ссылка на созвон от преподавателя уходит ученику.

5. Выдать работу.
6. Проверить уведомления:
   - новая домашняя работа;
   - новая классная работа;
   - работа проверена;
   - работа возвращена на доработку;
   - комментарий преподавателя.

7. Нажать кнопки обратной связи под уведомлением:
   - `Пришло`;
   - `Продублировалось`;
   - `С опозданием`;
   - `Не должно быть`;
   - `Некорректная ссылка`;
   - `Несколько вариантов`.

8. Ожидаемый результат:
   - после выбора кнопки остальные кнопки исчезают;
   - создателю/админу приходит один отчет;
   - при выборе нескольких вариантов бот ждет сообщение с номерами;
   - не появляется `Неизвестная команда`.

## 7. Визуальная целостность

1. Пройти основные страницы в светлой теме.
2. Пройти основные страницы в темной теме.
3. Для каждой роли проверить:
   - одинаковая логика шапки и навигации;
   - нет случайно белых кнопок на темном фоне;
   - нет текста, который не читается;
   - нет налезания кнопок;
   - карточки не выглядят как с разных сайтов;
   - мобильная версия не создает горизонтальный скролл.

## 8. Что считается блокером релиза

- Любая 500-ошибка.
- Любая роль попадает в чужой кабинет.
- Ученик не может открыть задания, теорию, комнату или профиль.
- Картинки заданий или теории массово не отображаются.
- Workspace теряет код после обновления.
- Таймер блокирует доработку.
- Telegram-уведомления ведут ученика на преподавательские страницы.
- Урок списывает неправильное количество занятий.
- Родитель видит инструменты редактирования вместо просмотра.

## 9. Что можно выпускать с пометкой "после релиза"

- Небольшие визуальные шероховатости, если текст читается и кнопки работают.
- Пустые состояния, которые понятны, но еще не идеально оформлены.
- Небольшая задержка live-sync, если данные не теряются.
- Неидеальная формулировка уведомления, если оно приходит вовремя и ведет по правильной ссылке.
