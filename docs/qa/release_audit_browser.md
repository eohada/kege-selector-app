# Браузерная ревизия релиза

Этот набор нужен, чтобы Codex мог проверять платформу не только по коду, но и как настоящий пользователь: открыть браузер, войти под разными ролями, нажимать страницы и ловить 500-ошибки, JS-ошибки и сломанные переходы.

## Подготовка локальных аккаунтов

```bash
venv_linux/bin/python scripts/seed_release_audit.py
```

Скрипт создает/обновляет QA-пул:

- `qa_pool_student_1`
- `qa_pool_tutor_1`
- `qa_pool_parent_1`
- `qa_pool_admin_1`

Пароль по умолчанию: `123456`.

Также создается связка:

- преподаватель `qa_pool_tutor_1` → ученик `qa_pool_student_1`
- родитель `qa_pool_parent_1` → ученик `qa_pool_student_1`

## Установка браузерного раннера

На машине нужен Node.js/npm. После установки Node:

```bash
npm install
npx playwright install chromium
```

Если не хочется менять зависимости проекта, можно оставить Playwright временным `npx`-инструментом. Команды `npm run test:e2e` уже используют `npx playwright ...`.

## Запуск

Быстрый HTTP-smoke без браузера:

```bash
venv_linux/bin/python scripts/release_http_smoke.py --base-url http://127.0.0.1:5000
```

Обычный прогон:

```bash
npm run test:e2e
```

С видимым браузером:

```bash
npm run test:e2e:headed
```

Полная релизная ревизия с отчетом:

```bash
npm run test:e2e:audit
```

То же самое, но медленно и в видимом браузере, чтобы можно было смотреть за действиями:

```bash
npm run test:e2e:audit:watch
```

После прогона отчет появится здесь:

```text
docs/qa/release_audit_report.md
```

Если локалка уже запущена на другом адресе:

```bash
BOOSTUDY_E2E_BASE_URL=http://127.0.0.1:5001 BOOSTUDY_E2E_SKIP_SERVER=1 npm run test:e2e
```

## Что проверяется сейчас

HTTP-smoke проверяет:

- вход под QA-ролями через настоящую форму логина;
- отсутствие HTTP 500 на ключевых страницах;
- отсутствие явных серверных error page-маркеров в HTML.

Playwright-smoke дополнительно проверяет:

- вход через обычную форму логина;
- ученик открывает кабинет, задания и тренажер;
- преподаватель открывает дашборд, работы, проверку и тренажер;
- родитель открывает родительский кабинет;
- админ открывает дашборд и QA-пул;
- тест падает при HTTP 500;
- тест падает при критичных ошибках в консоли браузера;
- при падении сохраняются trace/screenshot/video.

Это базовый smoke. Его задача не заменить ручную ревизию, а быстро ловить самые болезненные поломки после изменений.

Release-audit дополнительно делает скриншоты страниц и отмечает:

- сломанные изображения;
- горизонтальный скролл;
- почти пустые страницы;
- критичные ошибки консоли;
- HTTP 500+ в фоновых запросах;
- слишком мелкие кликабельные элементы как UX-заметку.

## Живая релизная проверка

Автотесты не заменяют ручной проход по настоящим сценариям. Полный русскоязычный маршрут лежит здесь:

```text
docs/qa/release_scenarios_ru.md
```

Там расписано, что именно проверить по ученику, преподавателю, родителю, администратору, Telegram, урокам, заданиям, workspace и визуальной целостности.
