# BooStudy AI Lab — Sprint 9 demo и ручная приёмка

Проверка проводится только на локальной AI Lab и синтетических заданиях. Не используйте реальные работы учеников. В Sprint 9 не выполнялись живые генерации GigaChat.

## Демонстрация семейств заданий

1. В Rubric Builder создайте или выберите утверждённую рубрику с точным `assignment_id` и `assignment_version`.
2. В Code Judge выберите связанный сохранённый набор тестов этой же версии и выполните эталонное решение. Сохраните принятый запуск.
3. Откройте `/admin/ai-lab/assignment-families` и создайте версию семейства. Укажите точные ID рубрики, набора тестов и эталонного запуска. В контракте каждому критерию рубрики сопоставьте требование и ссылку на версионированный источник.
4. Выполните проверку совместимости. Утверждение доступно только после успешной проверки и требует отдельного действия администратора.
5. В AI Homework Studio выберите точную версию задания и утверждённое семейство. Studio должна разрешить только совпадающие версии и приложить подтверждённый отчёт Code Judge.
6. Измените версию тестового набора и повторно разрешите семейство: система должна отказать в использовании устаревшей связи.

Параметры контракта проверяются по типу, диапазону, списку значений и default. В этой версии они не материализуют новые условия и не создают производные тесты: используйте семейство только для задания, смысл которого уже полностью покрыт указанными версиями критериев и тестов.

## Демонстрация конфликта оценки

На синтетическом запуске передайте подтверждённый Code Judge отчёт и ответ модели, в котором итоговый балл или критерий ему противоречит. Ожидается:

- технический балл Code Judge остаётся сохранён;
- конфликтующий педагогический комментарий получает статус блокировки/ручной проверки;
- обе попытки и токены доступны в истории;
- повтор ограничен настройкой и имеет явную причину;
- одинаковый ключ с тем же payload не создаёт новый вызов;
- тот же ключ с изменённым payload отклоняется.

Все проверки автоматизированы с replay провайдером; реальный GigaChat не вызывался.

## Quality Review: ручная приёмка

Откройте `/admin/ai-lab/quality-review` под admin. Выполните:

1. Проверьте общее число случаев и число ещё не просмотренных; убедитесь, что отображаются Homework, Course и Lesson.
2. Откройте случай с высоким техническим приоритетом. Убедитесь, что приоритет явно назван техническим и рядом показана причина; не трактуйте его как человеческую метку.
3. Сравните ожидаемый ответ с результатом модели и техническими доказательствами. Раскройте только нужные JSON-разделы.
4. Для одного применимого аспекта выберите «верно»/«неверно», для другого — «неприменимо». Сохраните оценку и комментарий.
5. Обновите страницу. Оценка должна загрузиться из отдельного журнала. Исходная запись результата модели должна остаться прежней; повторное сохранение той же оценки должно быть запрещено.
6. Оставьте часть аспектов без ответа и сохраните остальные. Пустой аспект должен учитываться как пропуск, а не как «неприменимо».
7. Пройдите элементы клавиатурой: переключатели, кнопки раскрытия, сохранение, переключение модуля и переход по истории должны быть доступны без мыши.

В контрольной серии Sprint 6/7 сейчас **0 экспертных меток из 22**. Тесты проверки N/A используют временную копию fixture и не создают метки в сохранённом наборе.

## Responsive проверка

Проверьте desktop, tablet и mobile на ширинах 1440, 1024 и 390 CSS px. Ожидается:

- нет горизонтальной прокрутки страницы;
- карточки, фильтры, панели доказательств и поля комментариев помещаются в viewport;
- технические JSON данные раскрываются без расширения всей страницы;
- приоритет и статус не перекрывают текст случая;
- действия сохранения доступны и не скрыты в узком viewport.

Браузерный инструмент ранее отказал в доступе к локальному URL по URL policy. Эти размеры в Sprint 9 фактически не осматривались; пункты выше являются ручным сценарием, а не отчётом о выполненном визуальном тесте.
