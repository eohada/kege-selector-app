# Side-сервисы и интеграции

## 1. Общая картина

В репозитории есть несколько важных подсистем, которые живут рядом с основным Flask-приложением, но не совпадают с ним по модели запуска.

## 2. `trainer_app/`

### Назначение

Отдельный Streamlit-интерфейс тренажёра для КЕГЭ.

### Как запускается

```bash
streamlit run trainer_app/app.py
```

### Как связан с основной платформой

- встраивается через iframe;
- использует внутренние `/internal/trainer/*` API основного Flask-приложения;
- зависит от shared secret;
- частично импортирует код из основного репозитория.

### Что важно помнить

- это отдельный процесс, но не полностью изолированный сервис;
- его нужно документировать и сопровождать вместе с основным trainer-контуром в `app/trainer/`.

## 3. `urep_bot/`

### Назначение

Shared utilities для production Telegram-интеграции платформы.

### Как устроен runtime

- production webhook обслуживается внутри Flask;
- `urep_bot` даёт конфиг, DB/session helpers и Telegram-related utility code;
- `run_bot.py` не является каноническим production entrypoint и служит legacy shim-ом.

### Практический вывод

Если проблема относится к production Telegram-функциям, смотреть нужно сразу в:

- `app/telegram/`
- `urep_bot/`
- `.env` / bot env vars

## 4. `telegram_bot/`

### Назначение

Независимый Telegram-бот для трекинга репортов от тестировщиков.

### Особенности

- отдельный runtime;
- отдельные env vars;
- собственная SQLite база репортов;
- не часть request-cycle основного продукта.

### Когда это важно

Не смешивайте этот бот с production webhook-контуром платформы. Это отдельный operational инструмент.

## 5. `scraper/`

### Назначение

Слой парсинга и синхронизации банка заданий.

### Как используется

- вызывается batch-скриптами из `scripts/`;
- работает с Playwright и/или API;
- обновляет основной task bank.

### Риски

- внешние зависимости и ToS/robots-ограничения;
- возможные массовые изменения данных в task bank;
- требования к backup/validation перед запуском.

## 6. Сравнение моделей запуска

| Подсистема | Модель запуска | Связь с основным приложением |
|------------|----------------|-------------------------------|
| `trainer_app` | отдельный Streamlit-процесс | тесная, через internal API и shared imports |
| `urep_bot` | логика внутри Flask webhook runtime | очень тесная |
| `telegram_bot` | отдельный bot process | слабая, operational-only |
| `scraper` | batch/scripts | пишет в общий task bank и косвенно влияет на платформу |

## 7. Практика документирования

- `trainer_app` документируйте как side-service с плотной связью;
- `urep_bot` документируйте как internal integration layer;
- `telegram_bot` — как отдельный operational подпроект;
- `scraper` — как batch ingestion layer, а не как пользовательский модуль платформы.
