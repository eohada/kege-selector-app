# BooStudy AI Lab — Sprint 9 report

**Результат:** локальная исследовательская интеграция укреплена и прошла целевую автоматическую регрессию. Это не подтверждение готовности к production.

## Что изменено

- Учёт каждого завершения GigaChat хранится отдельно: запрос, хеш payload, полный ответ, токены, параметры генерации, статус и причина повтора. По умолчанию разрешены не более двух попыток; автоматический повтор отключается конфигурацией. Начатая, но не разрешённая попытка после перезапуска не отправляется повторно автоматически.
- Идемпотентность основана на ключе запроса и отпечатке нормализованного payload. Повтор с тем же ключом и теми же данными возвращает сохранённый результат; повтор с другими входными данными отклоняется.
- При конфликте с подтверждённым Code Judge детерминированный балл сохраняется. Противоречащий педагогический комментарий блокируется, результат направляется на ручную проверку, а обе попытки и их расход остаются в истории.
- Добавлены версионируемые семейства заданий. Контракт связывает точный ID и версию задания, утверждённую рубрику, набор Code Judge, принятый эталонный запуск, правила критериев, ссылки с версиями и SHA-256. Переход выполняется явно: черновик → проверено → утверждено. Перед использованием связанные версии и хеш проверяются повторно.
- Analytics получает оценки критериев и из `criterion_scores`, когда Code Judge не приложен. Ранее эта форма ответа теряла критерии при переносе в доказательную запись.
- В Quality Review метки «неприменимо» и «пропущено» сохраняются отдельно и не входят в знаменатель точности. Приоритет очереди явно обозначен как технический, а не экспертный.
- Добавлены проверки точной совместимости семейств, повторного использования версий, устаревших ссылок, экспертных N/A, семантических конфликтов и длинной истории по нескольким синтетическим профилям.

Схема БД расширена миграцией `ai_lab_sprint9_families_retries`. Миграция скомпилирована; она не применялась к постоянной базе в рамках этого спринта.

## Текущая регрессия

Запущен объединённый целевой набор Sprint 3/4/6/7/8/9, Studio, Rubric Builder и Code Judge. Приложение и тесты запускались с новым временным SQLite-файлом; переменные подключения к внешней БД были очищены.

```powershell
python -m pytest -p no:cacheprovider -q --tb=short --show-capture=no tests/unit/test_ai_lab_sprint3.py tests/unit/test_ai_lab_sprint4.py tests/unit/test_ai_lab_sprint6_benchmark.py tests/unit/test_ai_lab_sprint6_history.py tests/unit/test_ai_lab_sprint6_resilience.py tests/unit/test_ai_lab_sprint7_review.py tests/unit/test_ai_lab_sprint8.py tests/unit/test_ai_lab_sprint9.py tests/v2/test_ai_lab_studio.py tests/v2/test_ai_rubric_builder.py tests/v2/test_code_judge.py
```

**Результат: 109 passed, 73 warnings за 78,03 секунды.** Предупреждения связаны с уже используемыми `Query.get()` и `datetime.utcnow()` в Flask/SQLAlchemy вспомогательных модулях; новых падений после обновления тестовых ожиданий не осталось. Дополнительно успешно прошли `py_compile` для изменённых AI Lab модулей, моделей и Sprint 9 миграции.

В набор входит `test_all_five_modules_flow_through_persistent_synthetic_sqlite`: он запускает сервисы Homework, Course, Lesson, Analytics и Practice на синтетических событиях в файловой SQLite базе, создаёт новое приложение поверх той же базы и проверяет восстановление сохранённых результатов. Тестовая база существует только в каталоге pytest `tmp_path` и удаляется после теста; постоянный синтетический DB-артефакт для ручного запуска не оставлен.

### Незапланированный локальный побочный эффект

В начале работы один диагностический вызов `flask db heads` импортировал приложение с его стандартной локальной конфигурацией. По логам это вызвало `db.create_all()`, локальную проверку/инициализацию схемы и bootstrap hooks в `instance/boostudy_dev.db`; команда Alembic upgrade не выполнялась. Файл был помечен как изменившийся по времени. Его содержимое не исследовалось и откат не предпринимался. После этого все команды приложения и тесты выполнялись с явно заданной изолированной БД. Это локальная БД разработки, не production; её состояние требует внимания владельца проекта.
