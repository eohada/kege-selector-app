# Данные и runtime-артефакты

## 1. Зачем нужен этот документ

В репозитории смешаны:

- исходные данные и reference-материалы;
- локальные и generated артефакты;
- runtime-каталоги;
- legacy и вспомогательные outputs.

Этот документ помогает не путать исходники продукта с эксплуатационным шумом.

## 2. Каталоги с предметными данными

### `data/`

Содержит разные классы материалов:

- локальные `.db` файлы;
- reference prototypes;
- reference solutions;
- JSON-артефакты и выгрузки;
- служебные backup/data snapshots.

Это не единый чистый source-of-truth каталог, а смешанная зона.

### `trainer_knowledge/`

Структурированные знания для trainer-контура. Это ближе к domain content, чем к runtime-мусору.

### `theory/`

Учебные материалы, связанные с теоретическим контуром проекта.

## 3. Runtime-каталоги

### `logs/`

Логи приложения. Должны считаться runtime-артефактами, а не постоянной частью исходников.

### `backups/`

Бэкапы БД. Критичны операционно, но не являются рабочими source-файлами приложения.

### `exports/`

Экспортные артефакты, включая generated training/fine-tuning outputs. Часть содержимого должна рассматриваться как generated data.

### `debug_out/`

Отладочные выгрузки и временные outputs.

## 4. Build и tool-артефакты

### `static/dist/`

Здесь лежит собранный CSS-артефакт. Источник находится в `static/src/`.

### `tools/tailwindcss/`

Локальный standalone tool-бинарник. Это вспомогательный инструмент среды разработки, а не часть доменной логики.

### `data/rag_hints/`

Generated индекс подсказок для RAG/LLM сценариев.

## 5. Legacy и псевдодокументы

### `qa_testing_files_md/`

Markdown-слепки файлов для QA/анализа. Это не narrative documentation и не исходники бизнес-логики.

### `boostudy2.0_examples/`

Демо/макеты/референсы интерфейса. Полезно как визуальный архив, но не как текущий UI source-of-truth.

### `legacy_backup/`

Исторические шаблоны и куски логики. Не считать активной частью системы без отдельной проверки.

## 6. Практический принцип

Если каталог:

- появляется после запуска скрипта;
- хранит локальные БД, логи, экспорты или временные данные;
- используется только для анализа, ревью или аварийной отладки;

то его нужно документировать как runtime/generated/legacy-артефакт, а не как канонический исходник проекта.
