# BooStudy AI Lab — локальная демонстрация Sprint 3.0

Демонстрация рассчитана на локальный backend и синтетические данные. Не запускать на production и не использовать реальные работы учеников.

## 1. Требования

- Локальный BooStudy запущен в режиме `local`, `AI_LAB_ENABLED=true`.
- Для запуска кода доступен существующий Docker Runner на loopback `127.0.0.1:8778` с текущим защитным профилем.
- Для запроса GigaChat локально заданы его учётные данные и доверенный CA bundle. Не вставляйте секреты в отчёты и формы диагностики.
- На время спринта использовались три разрешённых вызова GigaChat; повторять серию с внешней моделью без отдельного бюджета не нужно.

## 2. Rubric Builder

1. Войдите администратором и откройте `/admin/ai-lab/rubric-builder`.
2. Заполните синтетическое задание.
3. Чтобы переиспользовать рубрику, раскройте «Привязать к версии задания» и задайте устойчивый ID и версию. Для той же версии сохраняйте идентичное условие, предмет, тему, эталон и требования.
4. Повторный запрос с теми же данными вернёт сохранённую версию без генерации. При изменении задания увеличьте версию. Критерии остаются черновиком до проверки и ручного утверждения.
5. Просмотрите замечания по критериям, предложенные тесты и статус их подтверждения. Доверенный эталон запускайте только через sandbox Code Judge.

Без стабильного ID Builder не может безопасно сопоставить самостоятельные запросы и создаёт независимые рубрики; request key предотвращает лишь повтор одной и той же операции.

## 3. AI Homework Studio и воспроизводимый dev-набор

Откройте `/admin/ai-lab/studio` и используйте только задания `sum_multiples`, `count_vowels` и `clamp_list` из frozen dev fixture. Для локальной детерминированной проверки выполните:

```powershell
python scripts/run_ai_lab_sprint3_dev.py
```

Скрипт использует in-memory SQLite и существующий Docker Runner, проверяет хеш dev fixture и выполняет 12 вариантов кода. Он не читает holdout. Живой режим `--with-gigachat` делает до трёх генеративных запросов; он не запускался повторно после исчерпания разрешённого спринтового бюджета.

## 4. AI Analytics

Откройте `/admin/ai-lab/analytics` и выберите синтетический профиль. Сверяйте:

- размер выборки и число сохранённых событий;
- статусы навыков и повторяющиеся ошибки;
- доказательства и источники каждого вывода;
- предупреждения о недостаточности данных и ограниченность конечных тестов;
- динамику только там, где достигнут минимальный размер выборки.

Страница показывает отдельно демонстрационные профили и сохранённые AI Lab эксперименты. Это не анализ реальных учеников.

## 5. AI Practice

Откройте `/admin/ai-lab/practice` и выберите тот же синтетический профиль. Рекомендация появляется только при повторных технически подтверждённых ошибках, для которых есть соответствующее Python-задание. В карточке указаны основание, источник, тема, сложность и ограничения.

Если данных или подходящего задания недостаточно, страница показывает пустое состояние. Она не создаёт задание, не назначает домашнюю работу и не изменяет курс. Оценка полезности сохраняется только в текущем браузере.

## 6. Контракты будущих модулей

- `boostudy.course-analysis-input.v1` — read-only сведения о курсе и образовательные доказательства.
- `boostudy.lesson-intelligence-output.v1` — структурированный результат по синтетическому тексту урока.
- `boostudy.learning-evidence.v1` — общая типизированная запись результата с происхождением и статусом достоверности.

AI Course и AI Lesson Intelligence пока не являются рабочими генеративными модулями. Аудио и LiveKit не используются.

Подробные результаты и ограничения см. в [AI_LAB_SPRINT_3_REPORT.md](AI_LAB_SPRINT_3_REPORT.md).
