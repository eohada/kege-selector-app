# BooStudy AI Lab — итог Sprint 3.0

Дата проверки: 20 октября 2026 г. Все изменения и сценарии этого отчёта относятся к локальной AI Lab и синтетическим данным.

## Краткий итог

В спринте усилен Rubric Builder, сохранён воспроизводимый dev-набор AI Homework, добавлены работающие экраны AI Analytics и AI Practice, а между ними проведён синтетический интеграционный сценарий. Подготовлены типизированные контракты для будущих AI Course и AI Lesson Intelligence.

Схема БД не менялась: доказательства AI Homework сохраняются в существующем `quality_json`, а версии рубрик используют уже имеющиеся таблицы. Миграции не добавлялись и не запускались. Production, реальные `Submission`, рабочая локальная БД и профиль Docker Runner не изменялись.

Система остаётся локальной исследовательской средой. Малые выборки, контрольная выборка и неиспытанные после последнего исправления ответы модели не позволяют заявлять production-готовность.

## Реализовано

### AI Homework и Rubric Builder

- Валидатор проверяет обязательные поля, суммы, правила начисления, ссылки на критерии и поддерживаемые типы доказательств. Ошибки разделены на структурные и технические; содержательная корректность остаётся за экспертом.
- Частичное начисление принимается только при явном разрешении в требованиях. Отсутствующее обоснование вызывает замечание, а не подстановку выдуманного правила.
- Предложенные тесты проверяются и остаются неподтверждёнными до запуска доверенного эталона в Runner. Утверждение остаётся ручным.
- Генерация поддерживает локальный `AI_LAB_MAX_COMPLETION_TOKENS=3200`; обрезанный ответ сохраняется как `generation_error` с причиной и использованием токенов.
- Рубрику можно связать со стабильным ID и версией задания. Повторная генерация того же содержания возвращает последнюю сохранённую версию без вызова модели. То же ID и версия с изменённым условием дают понятный HTTP 409; для изменённого задания задаётся новая версия. Версии критериев сохраняются отдельно.
- В AI-пayload не передаются сценарии тестов; для педагогического ответа Code Judge отчёт очищается от скрытых проверок и их результатов. Повторный запуск модели после последнего исправления очистки не выполнялся из-за лимита внешних вызовов.

Сохранены существующие ручные оценки, история и сценарии Studio. Для задач без стабильного ID повторное использование между разными запросами не гарантируется; остаётся защита по request key.

### AI Analytics и AI Practice

- Analytics агрегирует типизированные результаты из сохранённых AI Lab экспериментов и отдельный синтетический демонстрационный набор. Выводы показывают основание, источник, ограничения и недостаточность наблюдений.
- Повторяющееся затруднение появляется только после подтверждений в разных заданиях. Одиночная ошибка отображается как недостаточность данных, а не как диагноз.
- Practice использует выводы Analytics и существующий каталог Python-заданий; рекомендация включает тему, сложность, источники доказательств и ограничения. Повторно выполненные задания исключаются. Предпосылки обозначаются как неизвестные, если доказательств нет.
- Оценка полезности рекомендации хранится только в браузере и не включается в метрики качества.
- Добавлены админ-страницы `/admin/ai-lab/analytics`, `/admin/ai-lab/practice` и JSON API для обоих модулей. Доступ проверяется по роли администратора.

### Общие контракты и защита

- `boostudy.learning-evidence.v1` различает технически подтверждённые факты, экспертные оценки, выводы AI, предположения и недостаточность данных.
- Для AI Course подготовлен read-only входной контракт: данные курса не изменяются.
- Для AI Lesson Intelligence задан контракт синтетического текстового результата. Аудио, транскрибация и LiveKit не подключались.
- Исполнение Python и профиль безопасности Docker Runner в рамках спринта не изменялись.

Браузерный smoke-тест выполнялся на отдельном временном сервере с SQLite `:memory:` и штатной формой входа. Пустой каталог упражнений в этом стенде корректно показал пустое состояние; интеграционный тест отдельно подставил синтетический каталог, чтобы проверить путь рекомендации. Состояние рабочей локальной БД не использовалось.

В ходе визуальной проверки обнаружено, что плавающая кнопка QA закрывала мобильное нижнее меню. Она стала компактной кнопкой 44×44 px над меню и получила доступное имя для скринридера. После перезапуска временного стенда геометрия и страницы проверены повторно.

### Замороженный dev-набор и Code Judge

Dev fixture содержит **3 задания и 12 решений**, включая альтернативные алгоритмы. SHA-256 fixture проверяется тестом; набор обозначен как `development`. Holdout не открывался и не использовался.

| Метрика Code Judge | Итог |
|---|---:|
| Совпадение итоговой оценки с экспертным ожиданием | **12/12** |
| Совпадение результатов критериев | **36/36** |
| Запуски Runner | **12** |

Использован существующий Runner: сеть отключена; непривилегированный пользователь; нет Docker socket, host mounts и секретов; сброшены capabilities; включены `no-new-privileges`, read-only root и seccomp. Ограничения: память 128 MB, CPU 1 core, PID 32, один одновременный запуск, очередь до 20, ожидание до 120 секунд, до 30 тестов, лимит вывода 64 KiB, таймаут до 2 секунд на тест, входной код до 64 KiB и набор тестов до 128 KiB.

### Ограниченная живая интеграция GigaChat

Выполнено **ровно 3** разрешённых генеративных вызова к `GigaChat-3-Pro`, без повторов. Каталог моделей и ответы фактически получены через provider; сценарии содержали альтернативно правильные решения из dev-набора.

| Запуск | Входные токены, включая кеш | Кешировано | Генерация | API total | Время ответа |
|---|---:|---:|---:|---:|---:|
| sum_multiples | 2 903 | 0 | 713 | 3 616 | 12.80 s |
| count_vowels | 2 826 | 0 | 693 | 3 519 | 12.80 s |
| clamp_list | 2 924 | 845 | 659 | 2 738 | 12.47 s |
| **Всего** | **8 653** | **845** | **2 065** | **9 873** | **38.06 s** |

Все три эксперимента завершились с `3/3`, семантической проверкой `valid`, одной попыткой и без конфликта с Code Judge. Вручную проверены три объяснения: баллы и критерии согласовались с эталонным ожиданием, альтернативные алгоритмы были приняты.

Ограничение ручной проверки: одно из первоначальных объяснений заявило, что прошли и скрытые тесты. Оно не раскрыло входы или ожидаемые результаты, но такое утверждение нежелательно; после этого добавлено исключение скрытых результатов из отчёта и явный запрет упоминать наличие/счётчик скрытых тестов. Повторно обращаться к GigaChat для проверки этой правки не стали, потому что разрешённый бюджет из трёх вызовов уже израсходован. Поэтому это исправление подтверждено тестом очистки payload, но ещё не новым живым ответом модели.

### Методика и границы метрик

- Точность Code Judge измерена на небольшом dev-наборе против зафиксированного экспертного oracle; это не оценка на независимом holdout.
- Три комментария GigaChat просмотрены вручную, `n=3`; автоматическая проверка статусов не считается экспертным измерением педагогического качества.
- Времена — сумма длительностей трёх ответов, не медиана и не SLA. Расход API приведён по фактическим полям usage; рублёвая стоимость не рассчитана без подтверждённого тарифа для этого ключа.
- Не измерялись production-эффективность, реальные навыки учеников, калибровка вероятности, полноценная точность рекомендованных тем и устойчивость на holdout.

## Что осталось

- Экспертная повторная оценка более крупной выборки AI-комментариев и независимый holdout не проведены.
- Пост-исправленная очистка упоминаний скрытых тестов не проверена новым live-вызовом GigaChat в этом спринте.
- Временный preview AI Practice был без каталога заданий; полный интерфейсный сценарий с реально существующим заданием каталога проверен интеграционным тестом с синтетическим элементом, но не на рабочей локальной БД.
- Автоматическая генерация и утверждение критериев по-прежнему ограничены ручным обзором. Стабильную повторную привязку нужно передавать в Builder: без ID и версии дедупликация между независимыми запросами невозможна.
- Анализ курса и интеллект урока пока представлены контрактами, а не рабочими AI-модулями. Учет полезности практики только локальный для браузера.
- Нет достаточной независимой выборки для заявлений о production-готовности или о педагогической калибровке модели.

## Итог

Спринт добавил рабочие локальные функции Analytics и Practice и соединил их через типизированные доказательства. Качество Code Judge на dev-наборе составило 12/12 по итоговой оценке и 36/36 по критериям; живая проверка GigaChat ограничена тремя успешными ответами. Эти цифры подтверждают работу локального прототипа на синтетических данных, но не готовность к автоматическому оцениванию реальных домашних работ.
