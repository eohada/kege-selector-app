# Быстрый старт: Проверка и перенос данных

## ✅ Что уже сделано

Вы уже:
- ✅ Создали базы данных PostgreSQL (production, sandbox, admin — по необходимости)
- ✅ Настроили переменные `DATABASE_URL` в окружении приложения

## 🔍 Шаг 1: Проверка подключений

### Способ 1: Через сервер (SSH / shell на хосте)

1. Подключитесь к серверу и перейдите в каталог приложения.
2. Запустите проверку БД (через скрипт или вручную):
   ```bash
   python -c "from app import create_app; from sqlalchemy import text; app = create_app(); app.app_context().push(); from app.models import db; db.session.execute(text('SELECT 1')); print('OK')"
   ```
3. Или откройте в браузере: **Админ → Диагностика** (`/admin/diagnostics`) и проверьте блок «База данных».

### Способ 2: Через веб-интерфейс

1. Откройте приложение в браузере (production / sandbox URL).
2. Если страница загружается без ошибок 500 — подключение к БД в порядке.

## 📦 Шаг 2: Перенос данных (если нужно)

⚠️ **Нужен только если у вас уже есть данные в старых базах.**

### Для Production

1. Узнайте URL старой и новой production-базы в панели хостинга.
2. На сервере (или там, откуда доступны обе БД):
   ```bash
   export OLD_PRODUCTION_DATABASE_URL="postgresql://старая_база"
   export NEW_PRODUCTION_DATABASE_URL="postgresql://новая_база"
   python scripts/migrate_to_centralized_db.py production
   ```

### Для Sandbox

1. Узнайте URL старой и новой sandbox-базы.
2. Запустите:
   ```bash
   export OLD_SANDBOX_DATABASE_URL="postgresql://старая_база"
   export NEW_SANDBOX_DATABASE_URL="postgresql://новая_база"
   python scripts/migrate_to_centralized_db.py sandbox
   ```

## 🎯 Шаг 3: Проверка результата

1. В логах миграции должно быть: `✅ Перенос завершен! Всего записей: X`.
2. Откройте приложение в браузере и убедитесь, что данные отображаются.
3. Проверьте подключение ещё раз: **Админ → Диагностика** или команда из «Способ 1» выше.

## ❓ Частые вопросы

### Базы пустые — это нормально?

**Да.** Новые базы пустые по умолчанию. Таблицы создаются при первом запуске приложения (`db.create_all()` + `ensure_schema_columns`).

### Как проверить, что таблицы созданы?

Через **Админ → Диагностика** или см. `docs/QUICK_DATABASE_CHECK.md`.

### Ошибка «URL не установлен»

Проверьте, что в окружении сервиса задана переменная `DATABASE_URL` (или `DATABASE_EXTERNAL_URL` / `POSTGRES_URL` при необходимости).

### Ошибка подключения

1. Убедитесь, что БД запущена и доступна.
2. Проверьте, что `DATABASE_URL` правильный (внешний URL, если подключаетесь с другой машины).
3. Для локального запуска против удалённой БД используйте внешний (public) URL, а не внутренний адрес хоста.

## 🔄 Миграции схемы (колонки, таблицы)

Отдельный скрипт для синхронизации схемы не нужен. Миграции выполняются **автоматически при старте приложения** через `ensure_schema_columns(app)`. Достаточно задеплоить новую версию и перезапустить сервис.
