# Состояние документации

## 1. Главные проблемы, найденные в ходе аудита

### Противоречие по предметной области

- `README.md` описывает платформу как систему подготовки к ЕГЭ по информатике.
- `docs/PROJECT_STRUCTURE_FULL.md` в старой версии говорил о ЕГЭ по математике.
- `docs/USER_SCENARIOS.md` тоже отсылает к математике.

Вывод: часть документации наследует старый или смешанный продуктовый контекст.

### Устаревшая точка входа

В ряде документов встречается `app.py` как основной entrypoint, хотя актуальная web-точка входа — `wsgi.py`.

Это было замечено, в том числе, в:

- старой версии `docs/PROJECT_STRUCTURE.md`;
- `docs/SCHEDULE_IMPLEMENTATION.md`;
- `docs/KNOWLEDGE_REQUIREMENTS.md`;
- некоторых плановых файлах.

### Смешение текущего устройства и исторических планов

В `docs/` рядом лежат:

- актуальные runbooks;
- планы рефакторинга;
- продуктовые roadmaps;
- исследовательские заметки;
- QA-чеклисты;
- операционные инструкции.

Без сильного индекса это делало каталог трудно масштабируемым.

## 2. Что теперь считается каноническим

Для общего понимания системы приоритет имеют:

- `README.md`
- `docs/README.md`
- `docs/PROJECT_STRUCTURE.md`
- `docs/PROJECT_STRUCTURE_FULL.md`
- разделы `docs/architecture/`, `docs/setup/`, `docs/operations/`, `docs/modules/`, `docs/audit/`

## 3. Что считать специализированным знанием

Следующие файлы сохраняют ценность, но не должны заменять общий архитектурный обзор:

- docs по remote admin;
- docs по diagnostics/logging;
- schedule/QA runbooks;
- feature-spec и plan-файлы;
- отдельные root-level markdown инструкции.

## 4. Что считать историческим или требующим сверки

### Высокий приоритет на сверку

- документы, где фигурирует `app.py` как текущий entrypoint;
- документы, где проект описан как математическая платформа;
- документы, написанные как roadmap/spec, но используемые как будто это текущее техническое описание.

### Средний приоритет на сверку

- файлы с привязкой к старой docker/deploy модели;
- старые QA-артефакты и narrative docs без даты и контекста;
- материалы, ссылающиеся на несуществующие или уже недоминантные каталоги.

## 5. Договорённости на будущее

- любой новый общий документ должен попадать под индекс в `docs/README.md`;
- архитектурные и operational truth-файлы не должны смешиваться с roadmap/идеями;
- устаревшие документы лучше помечать как historical/plan/audit context;
- перед изменением точек входа, env vars или deploy-модели нужно обновлять сначала канонические docs, а затем специализированные runbooks.
