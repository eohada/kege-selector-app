# Реестр cleanup-кандидатов

Этот реестр не означает немедленное удаление. Он нужен для безопасной инвентаризации беспорядка.

## Статусы

- `оставить` — активная и полезная часть репозитория.
- `перенести` — лучше хранить в другом месте или под другим индексом.
- `архивировать` — исторически полезно, но не должно выглядеть как текущий source-of-truth.
- `кандидат на удаление` — вероятный мусор или технический долг, но удалять только после отдельной проверки.

## 1. Корневые markdown-файлы

| Путь | Статус | Комментарий |
|------|--------|-------------|
| `README.md` | оставить | Канонический вход в репозиторий |
| `DEPLOY_TELEGRAM_WEBHOOK.md` | оставить | Специализированный runbook, полезен для production Telegram webhook |
| `REFERRAL_NOTIFICATIONS_SETUP.md` | перенести | Лучше жить в `docs/operations/` или специализированном разделе |
| `QUICK_SETUP_REFERRAL_NOTIFICATIONS.md` | перенести | То же, что выше |
| `DEBUG_REFERRAL_NOTIFICATIONS.md` | перенести | Специализированный debug runbook, не должен засорять корень |
| `DEBUG_REFERRAL_STEP_BY_STEP.md` | перенести | То же |
| `implementation_plan.md` | архивировать | Плановый документ, не должен восприниматься как текущее описание системы |

## 2. Legacy-каталоги

| Путь | Статус | Комментарий |
|------|--------|-------------|
| `legacy_backup/` | архивировать | Исторический код и шаблоны; полезно для раскопок, опасно как ложный источник истины |
| `boostudy2.0_examples/` | архивировать | Макеты/визуальные референсы, не текущий UI source |
| `qa_testing_files_md/` | перенести | Лучше держать как QA artifact каталог вне narrative docs слоя |

## 3. Runtime и generated зоны

| Путь | Статус | Комментарий |
|------|--------|-------------|
| `logs/` | оставить | Runtime-каталог, не удалять автоматически из рабочей среды |
| `backups/` | оставить | Эксплуатационно важный каталог |
| `exports/` | оставить | Generated outputs, но каталог нужен |
| `debug_out/` | кандидат на удаление | Если пустой или содержит старые локальные отладочные артефакты |
| `data/rag_hints/` | оставить | Generated индекс, но ожидаемая operational зона |
| `tools/tailwindcss/` | оставить | Dev tool directory, хотя бинарник должен оставаться локальным |

## 4. Документы в `docs/`

| Категория | Статус | Комментарий |
|-----------|--------|-------------|
| `REMOTE_ADMIN_*`, `ADMIN_*`, `RESET_ADMIN_USER.md` | оставить | Узкоспециализированные operational docs |
| `AUDIT_LOG_*`, `LOGGING.md`, `DIAGNOSTICS_*`, `DEBUG_GUIDE.md` | оставить | Полезные диагностические runbooks |
| `SCHEDULE_*`, `QA_*`, `PLATFORM_USER_GUIDE.md` | оставить | Рабочие сценарии и чеклисты |
| `UPDATE_PLANS.md`, `ONLINE_SCHOOL_*`, `ASSIGNMENTS_REFACTOR_PLAN.md`, `TASK_BASE_AND_LLM_PLAN.md`, `GIGACHAT_FINETUNING_PLAN.md` | архивировать | Ценные как планы и контекст, но не как текущее устройство системы |
| `KNOWLEDGE_REQUIREMENTS.md` | архивировать | Исследовательский материал, содержит legacy-упоминания |
| `ANALYTICS_MODULE_SPEC_ADAPTATION.md` | оставить | Спецификация/контекст, но не canonical architecture file |

## 5. Скрипты и one-off утилиты

| Группа | Статус | Комментарий |
|--------|--------|-------------|
| bootstrap/setup scripts | оставить | Часть рабочего инструментария |
| diagnostics/read-only scripts | оставить | Полезны для эксплуатации |
| production-write scripts | архивировать | Лучше явно пометить и изолировать в будущем |
| incident-specific underscore scripts | кандидат на удаление | После отдельного анализа ценности и воспроизводимости |
| destructive scripts вроде `strip_all_comments.py` | кандидат на удаление | Очень высокий риск, низкая предсказуемость пользы |

## 6. Что уже нельзя считать беспорядком

Новая docs-структура в:

- `docs/architecture/`
- `docs/setup/`
- `docs/operations/`
- `docs/modules/`
- `docs/audit/`

является новым организующим слоем и не должна восприниматься как ещё одно дублирование старых файлов.

## 7. Рекомендуемая следующая волна чистки

Безопасная последовательность на будущее:

1. Перенести специализированные root-level markdown-файлы в `docs/operations/` или `docs/archive/`.
2. Пометить плановые и исторические документы в `docs/` явным префиксом или отдельным архивным разделом.
3. Разобрать `legacy_backup/`, `boostudy2.0_examples/`, `qa_testing_files_md/` на предмет реально нужных артефактов.
4. Отдельно ревизовать dangerous scripts и one-off underscore utilities.

До отдельного подтверждения пользователя этот реестр остаётся только описанием, а не инструкцией на удаление.
