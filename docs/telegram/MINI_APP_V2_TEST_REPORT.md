## 2. Подробная матрица проверок Mini App V2

### 2.1. Криптография и аутентификация (`WebAppData` HMAC-SHA256)
- **Корректный расчёт HMAC:** Тест `test_validate_init_data_success` генерирует каноническую строку проверки `data_check_string`, вычисляет `secret_key = HMAC-SHA256("WebAppData", bot_token)` и сверяет подпись. Проверено: парсинг вложенного JSON `user` выполняется безопасно.
- **Защита от фальсификации (Tampering):** Тест `test_validate_init_data_tampered_signature` проверяет попытку подмены `user_id` или изменения контрольной суммы. Запрос немедленно отклоняется (`None`).
- **Защита от повторного воспроизведения (Replay Attack):** Тест `test_validate_init_data_expired_replay` подтверждает, что `auth_date` старше 24 часов (86400 с) блокируется сервером, даже если подпись валидна.
- **Защита от рассинхронизации часов (Future Drift):** Тест `test_validate_init_data_future_clock_drift` отклоняет доказательства из будущего (> 60 с).

### 2.2. Защита ролевой модели и RBAC-авторизация
- **Предотвращение эскалации привилегий:** Тест `test_bootstrap_creator_context_switch_and_escalation_guard` проверяет, что когда аккаунт ученика запрашивает переключение в контекст `creator` или `admin`, сервер игнорирует запрос и оставляет активным только `student`.
- **Безопасное переключение Создателя:** Создатель может переключаться между контекстами `creator` и `teacher`, получая соответствующие ролевые инструменты и экраны.
- **Строгая изоляция IDOR (Parent / Student):** Тест `test_parent_child_detail_and_idor_isolation` проверяет, что родитель имеет доступ только к детям, подтверждённым через `FamilyTie.is_confirmed == True`. Попытка запросить чужого ученика по ID возвращает `HTTP 403 foreign_child_forbidden`.
- **RBAC метрик платформы:** Тест `test_operations_health_rbac` подтверждает, что эндпоинт `/tg-app/api/operations/health` блокирует обычных пользователей с `HTTP 403` и доступен исключительно Создателю и Администраторам.

### 2.3. Домашние задания и расписание
- **Детализация ДЗ и фидбек:** Тест `test_student_assignment_detail_flow` проверяет выдачу дедлайна, описания, процента выполнения и комментария преподавателя. Несуществующие задания изолируются с `HTTP 404`.

## 4. Анализ работы внутри Telegram WebView и план HTTPS-туннелирования

### 4.1. Почему Telegram WebApp требует HTTPS
По спецификации платформы Telegram:
- Кнопки типа `InlineKeyboardButton(web_app=WebAppInfo(url=...))` **строго запрещают** протокол `http://`. Серверы Telegram Bot API возвращают `HTTP 400 Bad Request: URL must start with "https://"`.
- Внутри мобильного клиента Telegram открывает WebApp во встроенном защищённом контейнере WebView (WKWebView на iOS, WebView на Android), требующем валидный SSL-сертификат для обеспечения конфиденциальности криптографического токена `initData`.

### 4.2. Архитектурное решение в коде BooStudy (Fail-Safe Dual Mode)
В модуле `app/telegram/v3/ui.py` реализован интеллектуальный генератор кнопок `build_mini_app_button()`:
1. **В боевом режиме (HTTPS):** Если `APP_URL` или `TELEGRAM_MINI_APP_URL` начинается с `https://`, бот создаёт нативную кнопку `web_app=WebAppInfo(url=...)`, которая открывает Mini App прямо внутри шторки Telegram.
2. **В локальном режиме без туннеля (HTTP):** Если URL имеет вид `http://127.0.0.1:5000/tg-app`, бот формирует обычную URL-кнопку `📱 Открыть Mini App (браузер)`, не вызывая 400-ошибку Telegram API. Это позволяет локально открывать и тестировать Mini App в Chrome/Safari/Edge.

### 4.3. Оценка рисков публичных туннелей (Security Risk Assessment)
В соответствии с правилами проекта автоматическое открытие внешних туннелей **не производилось**. Ниже представлена оценка рисков для владельца платформы:

| Фактор риска | Описание | Мера защиты |
|---|---|---|
| **Публичная доступность порта Flask** | Временный URL туннеля направляет входящий трафик из интернета на локальный порт `127.0.0.1:5000`. | Доступ к API защищён криптографической подписью `WebAppData` Telegram с привязкой к конкретному пользователю БД. Обычные эндпоинты сайта требуют сессионных кук. |
| **Утечка токена бота** | Доверие туннелю зависит от секретности токена. | Токен бота никогда не передаётся клиенту; клиент получает только `initData`, подписанную серверами Telegram. |
| **Нестабильность временных доменов** | Бесплатные домены ngrok/localtunnel меняются при каждом перезапуске. | Использование Cloudflare Tunnel Quick Tunnels (`trycloudflare.com`) без регистрации или статического именованного туннеля. |

### 4.4. Инструкция для владельца: запуск HTTPS-туннеля для тестирования в мобильном Telegram

Если владелец желает протестировать Mini App непосредственно внутри мобильного приложения Telegram на смартфоне:

#### Вариант А: Использование Cloudflare Tunnel (Рекомендуется — бесплатно, без регистрации, чистый HTTPS)
1. В отдельном окне терминала запустить:
   ```bash
   cloudflared tunnel --url http://127.0.0.1:5000
   ```
2. Cloudflare выдаст временный HTTPS-адрес, например:
   `https://random-words.trycloudflare.com`
3. Указать этот адрес в переменной окружения или запустить бота с ним:
   ```powershell
   $env:TELEGRAM_MINI_APP_URL = "https://random-words.trycloudflare.com/tg-app"
   ```
4. После этого кнопка «📱 Открыть Mini App» в `@BooStudy_local_bot` станет нативной WebApp-кнопкой и откроет Mini App на телефоне с полным нативным UX (шторка, haptics, BackButton).

#### Вариант Б: Тестирование в мобильном браузере по локальной сети
1. Узнать локальный IP компьютера (например, `192.168.1.100`).
2. Открыть на смартфоне в том же Wi-Fi: `http://192.168.1.100:5000/tg-app` (потребуется запуск Flask на `0.0.0.0`).
