## 4. Система уведомлений (Notifications V1)

### 4.1. Архитектура транзакционной надёжности
- **Двухфазное сохранение:** При создании события в `app.notifications.service.notify_user` запись `UserNotification` и запись `TelegramDelivery` создаются в единой транзакции базы данных. При сбое транзакции откатываются обе записи (подтверждено тестом `test_outbox_enqueue_failure_rolls_back_notification`).
- **Дедупликация и Debounce:** Однотипные события дедуплицируются с окном 120 секунд. Назначения домашних заданий накапливаются с окном debounce 300 секунд.
- **Безопасный Allowlist:** Метод `app.telegram.delivery.is_delivery_permitted` проверяет Chat ID получателя. Если Chat ID не входит в список разрешённых для локального тестирования (`854161398`), статус доставки выставляется в `cancelled` / `simulated`, гарантируя отсутствие спама реальным пользователям при работе с клоном продакшн-базы.

### 4.2. Живая сквозная верификация доставки
1. Скрипт `scripts/trigger_test_notification.py` сгенерировал реальное образовательное событие `lesson_scheduled` для User 4.
2. В таблице `telegram_deliveries` сформирована запись с ID `212`.
3. Фоновый диспетчер `Telegram outbox dispatcher` захватил запись в цикле:
   ```json
   {"level": "INFO", "module": "app.telegram.delivery", "event": "telegram_delivery_claimed count=1 limit=50"}
   ```

4. Уведомление успешно отправлено в Telegram Bot API:
   ```json
   {"level": "INFO", "module": "app.telegram.delivery", "event": "telegram_delivery_finished delivery_id=212 status=sent attempts=1"}
   ```
5. В `@BooStudy_local_bot` доставлена красивая карточка события с кнопками навигации и отметкой времени.
