# BooStudy Telegram Next 2.1 — Broadcast Center & Mass Messaging

## 1. Назначение и архитектура

Центр рассылок BooStudy Telegram Next 2.1 предоставляет безопасный пошаговый мастер отправки объявлений, новостей и организационных сообщений пользователям платформы с соблюдением ролевых прав (RBAC), расчётом активной аудитории и защитой от спама.

---

## 2. Матрица прав доступа (RBAC)

| Роль отправителя | Разрешённые аудитории | Категории сообщений | Область видимости |
| :--- | :--- | :--- | :--- |
| **Creator** (Создатель) | `all`, `students`, `teachers`, `parents` | `news`, `announcement`, `broadcast` | Вся платформа |
| **Admin** (Администратор) | `students`, `parents` | `announcement`, `broadcast` | Закреплённые пользователи |
| **Teacher** (Преподаватель) | `my_students` | `broadcast` | **Строго свои прикреплённые ученики** |
| **Student / Parent** | — | — | Только получатели |

Попытка преподавателя отправить рассылку чужим ученикам или всей платформе блокируется на уровне ядра (`_get_permitted_audiences`).

---

## 3. Шаги мастера рассылок в Bot V3

Интерфейс мастера реализован в `app/telegram/v3/screens/broadcast.py`:
1. **Шаг 1: Выбор аудитории (`v3:bc:aud:<target>`):**
   Отображаются только аудитории, разрешённые для роли отправителя.
2. **Шаг 2: Выбор шаблона / категории (`v3:bc:tpl:<id>`):**
   Предлагаются готовые шаблоны (экзамен, техработы, обновление материалов) либо стандартный текст.
3. **Шаг 3: Предпросмотр и расчёт охвата (`v3:bc:preview`):**
   Система выполняет точный расчёт реальных получателей:
   - Проверяется привязка Telegram (`telegram_chat_id is not None`).
   - Проверяется статус категории в гранулярных настройках каждого получателя (`is_notification_enabled_for_user`).
   - Отображается финальная цифра: `📊 Рассчитано получателей: N чел.`
   - Отображается визуальная карточка сообщения, оформленная каноническим шаблонизатором.
4. **Шаг 4: Подтверждение и отправка (`v3:bc:send`):**
   - Черновик очищается для защиты от повторного клика.
   - Создаётся запись в `TelegramBroadcasts` (`created_by`, `sender_role`, `title`, `category`, `total_recipients`).
   - Формируются транзакционные записи в Outbox (`TelegramDelivery`) с детерминированным ключом `telegram:broadcast:{broadcast_id}:{recipient_user_id}`.

---

## 4. Защита в среде разработки (Dev Safety)

В локальном окружении действует строгая изоляция:
- Любые реальные вызовы к Telegram Bot API разрешены **исключительно в чат Создателя (`854161398`)**.
- Для всех остальных получателей диспетчер Outbox фиксирует безопасную симуляцию доставки (`simulated / dev_dry_run`), сохраняя целостность логики без риска случайного спама реальным пользователям.
