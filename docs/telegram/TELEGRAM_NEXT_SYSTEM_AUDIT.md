## 1. Назначение и контекст экосистемы

Telegram-экосистема платформы BooStudy предназначена для непрерывного, безопасного и персонализированного сопровождения учебного процесса. Она объединяет пять ключевых категорий пользователей:
- **Преподаватели (Tutors / Teachers):** оперативный контроль расписания, уведомления о сдаче работ учениками, быстрая проверка и комментирование решений без необходимости постоянного нахождения за ПК.
- **Ученики (Students):** актуальный трекинг занятий, напоминания о дедлайнах домашних заданий, мгновенное получение проверенных работ с оценками и рекомендациями.
- **Родители (Parents):** прозрачный контроль за успехами детей, посещаемостью занятий и финансово-академическим балансом.
- **Администраторы (Admins):** мониторинг инцидентов, баг-репортов и ключевых операционных метрик платформы.
- **Создатель платформы (Creator):** сквозной доступ ко всем ролевым пространствам, переключение режимов ассистента и оперативное управление платформой.

## 3. Точки входа и командный интерфейс

| Команда | Обработчик | Описание и права |
| :--- | :--- | :--- |
| `/start [code/token]` | `handle_start_command` | Первичная инициализация, deep-link связывание аккаунта BooStudy с Telegram, онбординг. |
| `/menu` | `handle_menu_command` | Вызов главного домашнего экрана в текущем ролевом контексте. |
| `/role` | `handle_role_command` | Интерактивное меню переключения между доступными ролями (для мультиролевых аккаунтов). |
| `/settings` | `handle_settings_command` | Персональные настройки: уведомления, тихие часы, выбор часового пояса, отвязка аккаунта. |
| `/help` | `handle_help_command` | Справка по возможностям бота, контакты поддержки, инструкция по привязке. |
| `/unlink` | `handle_unlink_command` | Запрос на безопасную отвязку текущего Telegram-аккаунта от профиля BooStudy. |
| `/cancel` | `handle_cancel_command` | Отмена текущего ожидания ввода (например, ручного ввода кода привязки). |

## 4. Пространство Inline Callback-кнопок

Все callback-данные строго подчиняются префиксу `v3:` и гарантированно не превышают жесткий лимит Telegram API в **64 байта**:

| Префикс / Шаблон | Область | Назначение |
| :--- | :--- | :--- |
| `v3:nav:home` | Навигация | Возврат на главный экран текущего контекста. |
| `v3:nav:role_picker` | Навигация | Открытие списка переключения ролей. |
| `v3:ctx:switch:<role>` | Контекст | Смена активного ролевого контекста (`teacher`, `student`, `parent`, `admin`, `creator`). |
| `v3:tch:queue` | Преподаватель | Открытие очереди работ на проверку. |
| `v3:tch:q:<id>` / `v3:tch:q_item:<id>` | Преподаватель | Карточка сданной работы ученика (с кнопками проверки). |
| `v3:tch:students` | Преподаватель | Список всех прикрепленных учеников (через `relationship_scope`). |
| `v3:tch:stu:<id>` | Преподаватель | Карточка конкретного ученика (успеваемость, баланс). |
| `v3:tch:lessons` | Преподаватель | Расписание занятий на ближайшие дни. |
| `v3:stu:hw` | Ученик | Список домашних заданий (активные, просроченные, проверенные). |
| `v3:stu:hw_view:<id>` / `v3:stu:hw_item:<id>` | Ученик | Детальная карточка домашнего задания и результат проверки. |
| `v3:stu:schedule` | Ученик | Расписание предстоящих занятий ученика. |
| `v3:par:children` | Родитель | Список подтвержденных детей (`FamilyTie`). |
| `v3:par:child:<id>` | Родитель | Карточка успеваемости и баланса выбранного ребенка. |
| `v3:par:schedule:<id>` | Родитель | Расписание уроков конкретного ребенка. |
| `v3:adm:ops` | Администратор | Панель мониторинга и метрик платформы. |
| `v3:adm:bugs` | Администратор | Просмотр открытых баг-репортов платформы. |
| `v3:set:toggle_notif` | Настройки | Включение/выключение уведомлений. |
| `v3:set:quiet` | Настройки | Управление тихими часами. |

## 5. Модель безопасности и RBAC

1. **Серверная авторизация на каждый callback:**  
   Пользователь не может получить доступ к данным чужой роли или другого пользователя путем подделки callback_data. Функция `check_domain_access` в `router.py` проверяет фактические роли пользователя в БД перед исполнением любого действия.
2. **Zero-IDOR защита при проверке ДЗ:**  
   Преподаватель не может просмотреть или проверить работу ученика, если задание было выдано другим преподавателем (даже если данный ученик занимается у обоих). Проверка осуществляется через `can_teacher_review_submission` (`Assignment.created_by_id == user.id OR Lesson.teacher_id == user.id`).
3. **Безопасная изоляция сред (Dev vs Production):**  
   - Использование токенов строго изолировано: в dev-режиме никогда не используется production-токен (`8581074364`).
   - По умолчанию в локальной разработке все уведомления отправляются в симулированном режиме (`simulated` dry-run), исключая спам реальным пользователям.
   - Живая отправка активируется только изолированно при явном opt-in (командная строка `--live` или файл `telegram_delivery_mode.json`) и строго для allowlist чатов.
4. **Валидация актуальности событий (Event Freshness):**  
   Перед отправкой каждого сообщения Outbox проверяет существование и состояние целевого объекта:
   - Отмененные уроки (`Lesson.status == 'cancelled'`) аннулируют уведомление.
   - Уже начавшиеся уроки аннулируют устаревшие напоминания.
   - Проверенные работы (`Submission.status == 'CHECKED'`) аннулируют устаревшие требования проверки.
   - Отозванные семейные связи (`FamilyTie.is_confirmed == False`) блокируют родительские дайджесты.

| Компонент | Статус | Примечания |
| :--- | :--- | :--- |

| **Tutor Core** | **Untouched** | Полная обратная совместимость, нулевое вмешательство в ядро репетитора. |
