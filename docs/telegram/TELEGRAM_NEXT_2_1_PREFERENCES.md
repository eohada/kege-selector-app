# BooStudy Telegram Next 2.1 — Granular Preferences & In-Bot Settings

## 1. Концепция гранулярных настроек по ролям

Ранее платформа предлагала плоский список из 12 общих переключателей в `UserProfile`. Если пользователь совмещал роли (например, Преподаватель и Ученик), отключение напоминаний ученика ломало рабочие оповещения преподавателя.

В Telegram Next 2.1 введена модель **раздельных настроек для каждой роли пользователя** (`UserNotificationPreference`), поддержанная иерархическим меню в Bot V3.

---

## 2. Модель базы данных `UserNotificationPreference`

Таблица `UserNotificationPreferences`:
- `id` (PK, Integer)
- `user_id` (FK `Users.id`, ondelete='CASCADE', indexed)
- `role` (String(32), indexed) — `student`, `teacher`, `parent`, `admin`, `creator`
- `event_kind` (String(64), indexed) — стабильный тип оповещения
- `is_enabled` (Boolean, default True)
- `created_at`, `updated_at` (DateTime, Europe/Moscow)
- Уникальное ограничение: `UniqueConstraint('user_id', 'role', 'event_kind')`.

### Иерархия разрешения статуса (Resolution Order):
1. **Глобальный выключатель:** `UserProfile.telegram_notifications_enabled`. Если False — блокируются все уведомления, кроме системных критических.
2. **Персональная настройка роли:** Запись `UserNotificationPreference(user_id, role, event_kind)`. Если найдена — её булево значение является определяющим.
3. **Фолбэк на legacy-профиль:** Поле `UserProfile.tg_notify_*`. Если пользователь ранее явно отключил категорию (`False`), этот осознанный отказ сохраняется и уважается.
4. **Системный дефолт роли:** Значение по умолчанию из `NotificationTypeRegistry.is_default_enabled(kind, role)`.

## 3. Иерархический интерфейс в Telegram Bot V3

Все экраны и коллбеки реализованы строго в модулях Bot V3 (`app/telegram/v3/screens/settings.py` и `router.py`):

```
[⚙️ Настройки]
  └─ [🔔 Настройка уведомлений]
       ├─ (Если мульти-роль) Выбор роли: 🎓 Ученик / 👨‍🏫 Преподаватель / 👨‍👩‍👧 Родитель
       └─ Меню категорий роли:
            ├─ 📅 Занятия и расписание (4/4 вкл)
            │    ├─ [✅] Назначение урока           [👁️ Пример]
            │    ├─ [✅] Пакетное назначение        [👁️ Пример]
            │    ├─ [✅] Перенос урока              [👁️ Пример]
            │    ├─ [✅] Отмена урока               [👁️ Пример]
            │    └─ [✅] Напоминание за 15 минут    [👁️ Пример]
            ├─ 📝 Домашние задания (3/4 вкл)
            │    ├─ [✅] Новое домашнее задание     [👁️ Пример]
            │    ├─ [✅] ДЗ проверено               [👁️ Пример]
            │    ├─ [✅] ДЗ возвращено на доработку [👁️ Пример]
            │    └─ [❌] Приближение дедлайна       [👁️ Пример]
            ├─ 💳 Баланс и занятия (3/3 вкл)
            ├─ 👨‍👩‍👦 Семья и связки (2/2 вкл)
            ├─ ⭐ Общее и дайджесты (1/2 вкл)
            └─ [🔄 Сбросить к настройкам по умолчанию]
```

## 4. Просмотр настроек учеников для преподавателей

Преподаватель имеет доступ к разделу **«👥 Уведомления моих учеников»**:
- **Строгий RBAC:** Проверка связи `teacher_has_student(teacher_id, student_user_id)`. Попытка открыть чужого ученика немедленно пресекается ошибкой `403 Forbidden`.
- **Режим только для чтения (Read-only):** Преподаватель видит статус категорий ученика, но не может менять их.
- **Режим сравнения «Что получу я / Что получит ученик»:** Наглядное объяснение шаблонов и подавления эхо-сообщений при сдаче, проверке и назначении уроков.

## 5. Административный аудит настроек (Admin / Creator)

В кабинетах Администратора и Создателя доступен раздел **«🛡️ Аудит уведомлений»**:
- **Обзор системных политик:** Просмотр дефолтов по каждой роли платформы.
- **Инспекция пользователей:** Детальный разбор статуса каждого типа уведомления с расшифровкой источника (provenance):
  - `[По умолчанию платформы]`
  - `[Личный выбор пользователя]`
  - `[Мигрировано из профиля]`
  - `[Глобально заблокировано]`
