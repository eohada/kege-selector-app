## 2. Проверка безопасности и изоляции данных (Security & IDOR Audit)

### 2.1. Защита от подделки параметров обратного вызова (IDOR Protection)
В рамках аудита устранены потенциальные векторы несанкционированного доступа к объектам:

1. **Кабинет ученика (`app/telegram/v3/screens/student.py`):**
   - **Угроза:** Манипуляция callback `v3:st:hw_item:<assignment_id>:<page>` позволяла бы читать заголовки и описания чужих ДЗ.
   - **Решение:** Добавлена серверная проверка `Submission.query.filter_by(assignment_id=assignment.assignment_id, student_id=student_obj.student_id)`. Если сдача не назначена ученику и пользователь не является Creator/Admin — возвращается экран **«Доступ ограничен»**.
   - **Тест:** `test_idor_student_foreign_assignment` — **PASSED**.

2. **Кабинет преподавателя (`app/telegram/v3/screens/teacher.py`):**
   - **Угроза:** Манипуляция callback `v3:tch:q_item:<submission_id>:<page>` позволяла бы просматривать сдачи учеников другого преподавателя.
   - **Решение:** Проверяется принадлежность ученика преподавателю (`student.mentor_id == user.id`) либо наличие привилегий Admin/Creator. При нарушении scope возвращается экран **«Доступ ограничен»**.
   - **Тест:** `test_idor_teacher_foreign_submission` — **PASSED**.

3. **Кабинет родителя (`app/telegram/v3/screens/parent.py`):**
   - **Угроза:** Запросы `v3:par:ch:<id>`, `v3:par:sch:<id>`, `v3:par:dig:<id>` могли раскрывать имя и данные чужих учеников.
   - **Решение:** Проверяется подтверждённая связь через `FamilyTie` (`build_parent_children(user)`). Если `student_id` не привязан к родителю, обращение к БД не выполняется, возвращается экран **«Доступ ограничен»** без утечки персональных данных.
   - **Тест:** `test_idor_parent_foreign_child` — **PASSED**.

4. **Панель администратора (`app/telegram/v3/screens/admin.py`):**
   - **Угроза:** Попытка прямого вызова экранов админки не-администратором.
   - **Решение:** Проверка `_can_access_admin(user)` на всех точках входа (`metrics`, `users`, `user_card`, `problems`) с корректным ответом на callback и отображением экрана **«Доступ ограничен»**.
   - **Тест:** `test_callback_dispatcher_rbac_rejection` — **PASSED**.

### 2.2. Защита Production от случайной активации (Fail-safe Guard)
В `app/telegram/config.py` реализован строгий механизм определения версии:
```python
def get_telegram_bot_version() -> str:
    explicit = (os.environ.get('TELEGRAM_BOT_VERSION') or '').strip().lower()
    if explicit in {'v2', 'v3'}:
        return explicit
    environment = (os.environ.get('ENVIRONMENT') or 'local').strip().lower()
    if environment in {'production', 'prod', 'staging', 'sandbox'}:
        return 'v2'
    return 'v3'
```
- В `production` без явного `TELEGRAM_BOT_VERSION=v3` запускается проверенная версия `v2`.
- В локальной разработке и тестовой среде по умолчанию активна `v3`.
- Проверено модульным тестом `test_telegram_bot_version_production_guard` — **PASSED**.

## 4. UX-аудит и навигация

1. **Хлебные крошки и возврат назад («◀ Назад»):**
   - На всех детальных карточках (`hw_item`, `q_item`, `st_item`, `u_item`, карточки детей) кнопка «◀ Назад» возвращает пользователя ровно в тот список и на ту страницу пагинации, с которой он пришёл, сохраняя активные фильтры (например: `v3:adm:u:2:student`).
   - Кнопка «🏠 Главная» всегда возвращает в корневой дашборд текущей активной роли.

2. **Защита от сбоев Telegram API (`Message is not modified`):**
   - В `render_screen` реализован безопасный перехват исключения `BadRequest: Message is not modified`. Повторное нажатие на ту же вкладку или обновление дашборда не генерирует ошибок в логах и завершается мягким подтверждением (`query.answer()`).

3. **Форматирование дат и времени на русском языке:**
   - Канонический хелпер `format_dt()` форматирует даты с учётом часового пояса пользователя (`Europe/Moscow` по умолчанию) и понятных относительных меток: `«Сегодня в 18:00 (через 2 ч)»`, `«Завтра в 11:30»`, `«Ср, 28 октября в 15:00»`.

4. **Адаптивные инлайн-клавиатуры:**
   - Пагинация оформлена компактной панелью: `[ ◀ ] [ 2 / 5 ] [ ▶ ]`.
   - Кнопки не выходят за лимиты Telegram Callback Data (64 байта) благодаря короткому префиксу `v3:`.

## 5. Инструкция для ручного тестирования владельцем платформы

Бот `@BooStudy_local_bot` запущен и готов к тестированию.

### Шаг 1. Проверка состояния привязки
1. Откройте в Telegram диалог с **`@BooStudy_local_bot`**.
2. Отправьте команду:
   ```text
   /status
   ```
3. **Ожидаемый результат:** 
   - Если аккаунт уже привязан: бот покажет ваше имя, активную роль и Chat ID.
   - Если аккаунт не привязан: отобразится экран приветствия с инструкцией по подключению.

---

### Шаг 2. Привязка аккаунта через код профиля
1. Войдите на локальный сайт под нужным пользователем:
   `http://127.0.0.1:5000/workspace/profile`
2. В карточке **«Telegram и уведомления»** нажмите кнопку **«Подключить Telegram»**.
3. Скопируйте сгенерированный 6-значный код (например, `BS-AB12CD`).
4. В Telegram отправьте боту этот код:
   ```text
   BS-AB12CD
   ```
   *(или с командой: `/link BS-AB12CD`)*.
5. **Ожидаемый результат:** Бот ответит сообщением *«🎉 BooStudy · Аккаунт привязан»* и откроет ваш рабочий кабинет.

---

### Шаг 3. Навигация и главное меню
1. Отправьте команду:
   ```text
   /menu
   ```
2. Проверьте основные разделы вашего кабинета:
   - **Для Создателя (`creator`):** Нажмите кнопку *«🔄 Переключить в режим Преподавателя»* — интерфейс мгновенно перестроится под уроки и проверку работ. Нажмите повторно — вернётся режим Создателя.
   - **Для Преподавателя (`teacher`):** Нажмите *«📥 Очередь проверки»* — просмотрите список сданных работ с пагинацией `[◀] [1/N] [▶]`. Откройте карточку работы и нажмите *«◀ Назад»* — вы вернётесь в очередь на ту же страницу.
   - **Для Ученика (`student`):** Нажмите *«📝 Домашние задания»* — проверьте отображение статусов заданий (*🟢 Сдано, 🟡 На проверке, ⚪ Назначено*).
   - **Для Родителя (`parent`):** Нажмите на карточку ребёнка — проверьте расписание и дайджест.

---

### Шаг 4. Смена роли (Role Switcher)
1. Отправьте команду:
   ```text
   /role
   ```
2. Если у вашей учётной записи несколько ролей (например, Создатель + Преподаватель), появится меню выбора активного кабинета.
3. Выберите нужную роль — дашборд переключится без необходимости повторной авторизации.

---

### Шаг 5. Настройки уведомлений и отвязка
1. Отправьте команду:
   ```text
   /settings
   ```
2. Перейдите в *«🔔 Категории уведомлений»*.
3. Нажмите на любой пункт (например, *«Напоминания об уроках»*) — статус мгновенно переключится между `✅ Вкл` и `❌ Выкл` с сохранением в базе данных.
4. Вернитесь в настройки и выберите *«🔓 Отвязать Telegram от профиля»*.
5. Нажмите *«◀ Отмена»* (чтобы сохранить привязку) либо *«❌ Да, отвязать аккаунт»* для проверки сценария отвязки.
