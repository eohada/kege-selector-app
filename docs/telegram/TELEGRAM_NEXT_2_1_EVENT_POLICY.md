# BooStudy Telegram Next 2.1 — Event Policy & Delivery Specification

## 1. Концепция и проблематика

В предыдущих версиях Telegram-бота платформа страдала от двух принципиальных дефектов:
1. **Самоуведомления (Self-notifications):** Пользователь получал эхо-сообщения о действиях, которые совершил сам (например, преподаватель создавал урок или проверял ДЗ и получал уведомление об этом в свой Telegram; ученик сдавал работу и получал «Вы сдали работу»).
2. **Лавина однотипных сообщений (Notification Flood):** При массовом добавлении занятий (от 3 до 5 уроков) ученик получал несколько однотипных карточек подряд.
3. **Дублирование при мульти-ролях:** Если аккаунт совмещал роли Создателя, Администратора и Преподавателя, одно системное или учебное событие могло породить несколько сообщений в один физический чат.

В версии 2.1 введена строгая событийная модель `EventContext`, политика подавления самоуведомлений, семантическая дедупликация и движок группировки массовых операций.

---

## 2. Структура `EventContext`

Каждое бизнес-событие платформы сопровождается контекстом происхождения:

```python
@dataclass(frozen=True)
class EventContext:
    event_kind: str
    actor_user_id: int | None = None
    actor_role: str | None = None
    subject_user_id: int | None = None
    entity_type: str | None = None   # lesson, submission, task, billing, system
    entity_id: int | None = None
    batch_id: str | None = None
    source: str = "web"              # web, bot, scheduler, celery, admin_action
    occurred_at: datetime = field(default_factory=utc_now)
```

## 3. Политика подавления самоуведомлений (`should_suppress_notification`)

### Правило 1: Подавление действий автора
Если `actor_user_id == recipient_user_id` и событие относится к классу действий автора:
- `lesson_scheduled` (Преподаватель или админ назначил урок)
- `lesson_rescheduled` (Пользователь перенёс урок)
- `lesson_cancelled` (Пользователь отменил урок)
- `homework_submitted` / `assignment_submitted` (Ученик сдал работу через веб)
- `homework_checked` / `assignment_graded` (Преподаватель выставил оценку)
- `homework_returned` / `assignment_returned` (Преподаватель вернул на доработку)
- `assignment_assigned` (Преподаватель выдал домашнее задание)

**Решение:** Уведомление в Telegram **подавляется**. Запись в Outbox не создаётся, логируется событие аудита:
`telegram_delivery_suppressed_self_action recipient_user_id=X actor_id=X kind=Y`

### Правило 2: Защита от ложных предположений
Если инициатор неизвестен (`actor_user_id is None`), система **никогда не домысливает** получателя как автора. Системные напоминания (за 15 минут до урока), утренние дайджесты и критические оповещения всегда доставляются адресатам.

## 4. Семантическая дедупликация мульти-ролей

Если физический пользователь обладает несколькими ролями (например, `Creator + Admin + Teacher + Student`):
1. Событие формирует детерминированный ключ:
   `telegram:semantic:{user_id}:{event_kind}:{entity_type}:{entity_id}:{batch_id}`
2. При наличии нескольких ролевых контекстов для одного `user_id` выбирается наиболее специфичная роль в соответствии с приоритетом:
   `student` → `teacher` → `parent` → `admin` → `creator`.
   - Если событие касается ученика, пользователь получает карточку в роли `student`.
   - Если событие касается проверки, пользователь получает карточку в роли `teacher`.
3. В один физический Telegram Chat ID доставляется **ровно одно** сообщение с корректными кнопками.

---

## 5. Движок батчинга массовых операций (`NotificationBatcher`)

При создании группы занятий (например, через сетку расписания):
1. Все уроки связываются единым идентификатором `batch_id`.
2. Порог срабатывания группировки: **$\ge 3$ занятий** для одного получателя.
   - Если $< 3$ уроков (1 или 2): генерируются стандартные индивидуальные карточки `lesson_scheduled`.
   - Если $\ge 3$ уроков: индивидуальные карточки подавляются. Генерируется ровно одна карточка `lesson_batch_scheduled`.
3. Содержимое батч-карточки:
   - Заголовок: `🗓️ Вам назначили N занятий` (или `🗓️ Назначено N занятий у ребёнка` для родителей).
   - Преподаватель и предмет.
   - Список до 5 ближайших уроков с датой, временем по МСК и темой.
   - Сноска `... и ещё N занятий в расписании`, если уроков больше 5.
   - Единая кнопка `📅 Моё расписание`.
4. Идемпотентность: `dedupe_key = f"telegram:batch:lesson_scheduled:{recipient_user_id}:{batch_id}"`. Повторный запуск батча исключает дублирование.
