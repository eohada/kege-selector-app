## 1. Архитектура безопасного изолированного HTTPS-доступа

### 1.1. Принцип нулевого доверия (Zero Trust Dev Gateway)
В соответствии с требованиями безопасности **категорически запрещено** открывать внешний туннель напрямую к порту Flask `5000`. При прямом туннелировании в интернет попадает вся платформа: административные разделы, API курсов, задачи, формы входа и внутренние служебные маршруты.

Для безопасного тестирования Telegram Mini App V2 разработан и внедрён специализированный обратный прокси-шлюз **[`scripts/mini_app_gateway.py`](file:///f:/projects/kege_selector_app_current/scripts/mini_app_gateway.py)**:

```
[ Telegram App (Phone / Desktop) ]
                │
                │ HTTPS (TLS 1.3)
                ▼
      [ Cloudflare Tunnel ]
                │
                │ HTTP (localhost only)
                ▼
  [ Mini App Gateway: 127.0.0.1:5050 ] ───► Блокировка 403 (/admin, /login, /api, etc.)
                │
                │ Санитизированный прокси-трафик (только /tg-app/*, Cookie stripped)
                ▼
    [ BooStudy Flask: 127.0.0.1:5000 ]
                │
                ▼
      [ SQLite: boostudy_dev.db ]
```

## 2. Комплекс мер безопасности перед открытием доступа

### 2.1. Криптографическая валидация `initData` (RFC Telegram WebApp)
- Сервер не доверяет никаким идентификаторам из тела JSON без валидации подписи.
- Хэш вычисляется по алгоритму Telegram: `HMAC-SHA256("WebAppData", bot_token)`.
- Подделка любого байта или параметра приводит к мгновенному отказу (`HTTP 403 invalid_init_data`).
- Просроченные токены (> 24 ч) и токены из будущего (> 60 с) отклоняются.

### 2.2. Защита от эскалации привилегий и IDOR
- **Изоляция ролей:** Обычный ученик не может получить доступ к API преподавателя или создателя, передавая `requested_context`. Сервер принудительно фиксирует контекст на уровне реальных ролей пользователя в БД.
- **Изоляция учеников:** Запрос деталей домашнего задания проверяет принадлежность работы текущему ученику.
- **Изоляция преподавателей:** Расписание фильтруется по `Student.mentor_id == teacher.id`. Чужие ученики не попадают в выдачу.
- **Изоляция родителей:** Эндпоинт `/tg-app/api/parent/child/detail` требует активную подтверждённую запись `FamilyTie(is_confirmed=True)`. Чужие ученики блокируются с `HTTP 403 foreign_child_forbidden`.

### 2.3. Серверный Allowlist Telegram ID
В `app/telegram/mini_app.py` внедрён серверный фильтр доверенных Telegram ID:
- При активации режима `TELEGRAM_MINI_APP_ALLOWLIST_ONLY=1` сервер проверяет `tg_id` из `initData` по списку `TELEGRAM_MINI_APP_ALLOWLIST_CHAT_IDS`.
- Аккаунт Создателя (Telegram ID `854161398`) включён в доверенный список по умолчанию.
- Любой посторонний пользователь Telegram, открывший ссылку на Mini App, получает `HTTP 403 telegram_id_not_allowlisted` с понятным уведомлением в интерфейсе.

### 2.4. Санитизация заголовков и защита сессий
- Шлюз **полностью удаляет заголовок `Cookie`** при проксировании запросов к `/tg-app/api/*`. Это гарантирует, что Mini App никогда не использует куки сессии браузера и аутентифицируется исключительно через подлинный Telegram `initData`.
- Заголовок `Host` переписывается на `127.0.0.1:5000`, блокируя атаки Host Header Injection.
- Заголовки `X-Forwarded-Host`, `X-Forwarded-Prefix`, `X-Original-URL`, `X-Rewrite-URL` вырезаются.

### 2.5. Анализ предупреждений pytest
В ходе аудита были детально проанализированы предупреждения SQLAlchemy:
- Вызовы устаревшего API `Model.query.get(id)` модернизированы до стандарта SQLAlchemy 2.0: `db.session.get(Model, id)`.
- В тестовом модуле `test_telegram_mini_app_v2.py` количество предупреждений снижено до **0**.

## 3. Скрипт управления туннелем: `scripts/tunnel-mini-app.ps1`

Для автоматизации запуска, мониторинга и выключения разработан PowerShell-сценарий **[`scripts/tunnel-mini-app.ps1`](file:///f:/projects/kege_selector_app_current/scripts/tunnel-mini-app.ps1)**.

### 3.1. Проверка статуса
```powershell
powershell -File "scripts/tunnel-mini-app.ps1" -Status
```
Выводит статус шлюза (порт 5050), активность туннеля и выполняет контрольный зонд защитного периметра (проверка блокировки `/admin`).

### 3.2. Активация безопасного доступа (после разрешения владельца)
```powershell
# Шаг 1: Запуск Cloudflare Tunnel к изолированному шлюзу 5050 (в отдельном окне):
cloudflared tunnel --url http://127.0.0.1:5050

# Шаг 2: Активация шлюза и передача адреса боту:
powershell -File "scripts/tunnel-mini-app.ps1" -Start -PublicUrl "https://<your-subdomain>.trycloudflare.com"
```
Скрипт:
1. Запускает `mini_app_gateway.py` в фоне на `127.0.0.1:5050`.
2. Записывает конфигурацию в неотслеживаемый файл `instance/mini_app_tunnel_env.json`.
3. Перезапускает `@BooStudy_local_bot` с активным `TELEGRAM_MINI_APP_URL`.
4. Бот мгновенно генерирует нативную кнопку `WebAppInfo`.

### 3.3. Экстренное и штатное отключение (1 команда)
```powershell
powershell -File "scripts/tunnel-mini-app.ps1" -Stop
```
Скрипт:
1. Останавливает процесс шлюза `mini_app_gateway.py`.
2. Удаляет временную конфигурацию `instance/mini_app_tunnel_env.json`.
3. Сбрасывает переменные окружения.
4. Перезапускает Dev Bot в чистый локальный режим (без внешних ссылок).
5. Локальный Flask (`127.0.0.1:5000`) остаётся нетронутым и продолжает работать.

## 4. Программа WebView-приёмки для владельца

После запуска туннеля выполняется следующая программа проверки в Telegram Desktop и на мобильном устройстве:

### 4.1. Авторизация и запуск (Creator)
- [ ] Открыть диалог с `@BooStudy_local_bot`.
- [ ] Отправить команду `/start` или нажать `🔄 Обновить` на главном экране.
- [ ] Убедиться, что верхняя кнопка отображает **«📱 Открыть Mini App»** (со значком WebApp, а не внешней стрелкой).
- [ ] Нажать на кнопку: приложение должно открыться во встроенной шторке Telegram WebView без открытия внешнего браузера.
- [ ] Индикатор статуса: зелёная пульсирующая точка (Online).
- [ ] Бейдж профиля: аватар, имя пользователя `creator`, плашка роли `Создатель`.

### 4.2. Ролевые сценарии и переключение контекста
- [ ] **Главный экран Создателя:** отображение карточек метрик платформы, активных задач Action Center, очереди баг-репортов.
- [ ] **Переключение в режим Преподавателя:** нажать кнопку переключения в шапке (чип `Преподаватель`).
- [ ] **Кабинет Преподавателя:**
  - Вкладка «Очередь проверки»: отображение сданных домашних заданий.
  - Вкладка «Расписание»: переход по дням недели (селектор 7 дней), отображение карточек уроков.
  - Нажатие на карточку урока: раскрытие модального окна с темой, учеником и кнопкой входа в комнату.
  - Нажатие на нативную кнопку Telegram `◀ Назад`: плавное закрытие модального окна без закрытия приложения.
- [ ] **Тактильный отклик (Haptics):** проверить виброотклик смартфона при смене вкладок нижней навигации и переключении тумблеров.
