# BooStudy Bot V3 — Архитектурная спецификация

> **Версия:** 3.0.0 (BooStudy Bot V3)  
> **Дата:** 2026-10-23  
> **Статус:** Принято к реализации  
> **Платформа:** BooStudy Educational Platform  

---

## 1. Введение и цели редизайна

Текущий пользовательский слой Telegram-бота (`app/telegram/handlers.py`, >5000 строк) страдал от следующих критических недостатков:
- **Монолитность и отсутствие разделения:** смешение низкоуровневых SQL-запросов, разметки сообщений и навигационной логики в одном гигантском модуле.
- **Устаревший UX:** огромные простыни неструктурированного текста, громоздкие ReplyKeyboards (например, генерация десятков кнопок пользователей), отсутствие внятной inline-навигации «Назад/Главная».
- **Уязвимости утечки данных:** старые текстовые обработчики (`"📅 Уроки на сегодня"`, `"📝 Очередь ДЗ"`) не изолировали выборки по текущему пользователю и отдавали общесистемные данные.
- **Смешение ролей:** отсутствие строгого, безопасного механизма переключения ролей для мульти-ролевых пользователей и Создателя.

**BooStudy Bot V3** полностью заменяет пользовательский слой бота на модульную, Telegram-native inline-архитектуру, опираясь на существующий сервисный фасад `app/telegram/application.py`, проверенную систему связывания `app/telegram/linking.py` и Outbox-инфраструктуру `app/telegram/delivery.py`.

## 2. Архитектурные принципы V3

1. **Тонкие обработчики (Thin Handlers):** Обработчики бота отвечают только за парсинг входных данных Telegram, вызов сервисного слоя и передачу результата в UI-движок.
2. **Нулевое дублирование бизнес-логики:** Вся доменная логика (выборка уроков, домашних заданий, прав доступа, расчет прогресса) извлекается исключительно через канонический фасад `app/telegram/application.py`.
3. **Безопасность Callback Data и Server-Side RBAC:** Callback data содержит только намерение (`v3:<domain>:<action>:<id>`). Роль и полномочия проверяются на сервере при каждом клике. Никаких прав из клиентского callback.
4. **Telegram-native UI:**
   - 100% inline-навигация под сообщениями.
   - Использование `edit_message_text` / `edit_message_reply_markup` для плавной навигации без замусоривания чата.
   - Обязательный `await query.answer()` для предотвращения индикатора вечной загрузки.
   - Пагинация для любых списков (ученики, ДЗ, пользователи, очередь проверки) с шагом и индикатором страниц (`◀ 1/4 ▶`).
   - Кнопки возврата: «◀ Назад» и «🏠 Главная».
5. **Безопасная миграция и Feature Toggle:**
   - Переменная окружения `TELEGRAM_BOT_VERSION` (значения `v3` и `v2`, по умолчанию `v3`).
   - Изоляция регистрации обработчиков в `webhook.py` и `polling.py`: либо регистрируется V3, либо V2.
   - Возможность мгновенного отката на V2 без изменения БД.

## 3. Структура пакета `app/telegram/v3/`

```text
app/telegram/v3/
├── __init__.py           # Экспорт ключевых точек входа
├── constants.py          # Константы роутера, префиксы callback, лимиты пагинации
├── identity.py           # Идентификация Telegram-пользователя, привязка, активность
├── context.py            # Мульти-ролевой менеджер (активный контекст, защита от эскалации)
├── ui.py                 # Telegram UI Engine: шаблоны карточек, клавиатуры, пагинатор, HTML-экранирование
├── router.py             # Центральный диспетчер команд и callback-кнопок
├── registry.py           # Регистрация обработчиков в telegram.ext.Application
├── toggle.py             # Диспетчер версий V2/V3
└── screens/              # Экраны и контроллеры предметных областей
    ├── __init__.py
    ├── base.py           # Базовый интерфейс экрана
    ├── unlinked.py       # Экран для непривязанных пользователей
    ├── student.py        # Кабинет Ученика (главная, расписание, ДЗ, прогресс)
    ├── teacher.py        # Кабинет Преподавателя (главная, уроки, очередь ДЗ, ученики)
    ├── parent.py         # Кабинет Родителя (главная, дети FamilyTies, дайджест)
    ├── admin.py          # Операционная панель Администратора (метрики, пользователи, поиск)
    ├── creator.py        # Кабинет Создателя (управление, переключение режимов Creator <-> Teacher)
    └── settings.py       # Общие настройки (роль, профиль, уведомления, отвязка, /help)
```

## 4. Спецификация Callback Data

Все inline-кнопки V3 следуют строгому префиксу `v3:` и формату:
`v3:<domain>:<action>[:<param1>[:<param2>]]`

Длина callback_data в Telegram ограничена 64 байтами. Использование коротких доменных кодов гарантирует отсутствие превышения лимита:

| Доменный код | Область ответственности | Примеры |
|---|---|---|
| `nav` | Общая навигация | `v3:nav:home`, `v3:nav:back` |
| `ctx` | Переключение ролевого контекста | `v3:ctx:menu`, `v3:ctx:set:teacher`, `v3:ctx:set:student` |
| `stu` | Сценарии ученика | `v3:stu:home`, `v3:stu:sch:today`, `v3:stu:hw:p:1`, `v3:stu:hw:v:42`, `v3:stu:prog` |
| `tch` | Сценарии преподавателя | `v3:tch:home`, `v3:tch:q:p:1`, `v3:tch:q:v:105`, `v3:tch:st:p:1`, `v3:tch:st:v:18` |
| `par` | Сценарии родителя | `v3:par:home`, `v3:par:ch:sel:3`, `v3:par:ch:sch`, `v3:par:ch:hw` |
| `adm` | Сценарии администратора | `v3:adm:home`, `v3:adm:u:p:1:all`, `v3:adm:u:v:91`, `v3:adm:probs` |
| `cre` | Сценарии создателя | `v3:cre:home`, `v3:cre:toggle_mode` |
| `set` | Настройки и уведомления | `v3:set:home`, `v3:set:notif:p`, `v3:set:notif:t:lesson`, `v3:set:unlink:ask`, `v3:set:unlink:do` |

## 5. Модель состояний и безопасность

### 5.1. Авторизация и контекст пользователя
1. При каждом обращении (`Update`) извлекается `chat_id` Telegram.
2. `resolve_identity(chat_id)` находит запись в `UserProfile` (и `User`).
3. Если пользователь не привязан — немедленно рендерится защитный экран `screens/unlinked.py` со ссылкой на генерацию кода в `/workspace/profile`.
4. Если пользователь привязан:
   - Обновляется `telegram_last_interaction_at`.
   - Запрашивается `resolve_active_context(user, requested_context)`.
   - Проверяется, что запрошенное действие разрешено для текущего контекста и роли.
   - При попытке несанкционированного доступа (например, ученик нажал скопированную callback-кнопку админа) — действие блокируется, выводится предупреждение `«Действие недоступно»`, а пользователь возвращается на свой домашний экран.

### 5.2. Сохранение контекста Создателя
Создатель (`creator`) имеет возможность переключаться в рабочий режим преподавателя (`creator_bot_mode = 'TEACHER'`) и обратно в режим платформы (`'ADMIN'`).
- При нажатии `v3:cre:toggle_mode` значение `user.creator_bot_mode` обновляется в базе данных.
- Состояние сохраняется между перезапусками процесса бота.

## 6. Взаимодействие с внешними модулями BooStudy

- `app/telegram/application.py` — единый источник подготовленных DTO:
  - `build_today_view`
  - `build_student_schedule`, `build_student_assignments`, `build_student_progress`
  - `build_teacher_review_queue`, `build_teacher_students`
  - `build_parent_children`, `build_parent_schedule`, `build_parent_digest`
  - `build_operational_summary`, `search_operational_users`
- `app/telegram/linking.py` — функции `unlink_telegram_identity`, `telegram_identity_is_linked`.
- `app/telegram/deep_links.py` — генерация безопасных ссылок на комнаты уроков и разделы веб-платформы.
- `app/telegram/notifications.py` — настройки категорий уведомлений в `UserProfile`.

## 7. Стратегия регрессионного тестирования

Автотесты V3 организуются в отдельном тестовом модуле:
- `tests/v2/test_telegram_v3_core.py` — тестирование роутера, идентификации, контекстов и безопасности.
- `tests/v2/test_telegram_v3_screens.py` — тестирование рендеринга всех экранов для каждой роли (ученик, преподаватель, родитель, админ, создатель, непривязанный).
- `tests/v2/test_telegram_v3_navigation.py` — тестирование пагинации, возврата назад, переключения ролей и обработки устаревших callback.
