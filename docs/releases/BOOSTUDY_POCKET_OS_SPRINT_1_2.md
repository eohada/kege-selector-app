## 1. Executive Summary & Goals

В Sprint 1.1 была успешно решена визуальная задача перехода на светлую тему BooStudy Light. Однако владелец продукта выделил критические проблемы эргономики и функциональной достоверности:
1. **Code Focus:** Редактор использовал только часть доступной высоты (был зажат в 480px из 844px), а в ландшафтной ориентации сжимался до 52% (440px из 844px), оставляя правую половину экрана пустой.
2. **WindowManager:** Инлайновые стили окон десктопа конфликтовали с мобильным слоем, а метод `ensureRoomWindowAccessible()` принудительно перетирал мобильные координаты.
3. **Детекция мобильного устройства:** Поворот экрана в landscape иногда ошибочно трактовался как десктоп из-за ширины 844px; отсутствовал fail-closed guard роли (учитель мог случайно активировать Pocket OS через `?pocket_os=1`).
4. **Реальное исполнение Python:** Вывод консоли требовал подтверждения реальными математическими вычислениями (не моками), отслеживания рассинхронизации редактора и консоли `(код изменён)`.
5. **Реальное Задание 5464:** Вместо синтетического текста требовалось загрузить реальную задачу 5464 из БД с графом дорог и весовой матрицей, обеспечить горизонтальный скролл таблицы, убрать статическую подсказку «Фокус урока», и подтвердить сдачу ответа `11` с проверкой в панели учителя.
6. **Двусторонняя синхронизация штрихов BooCanvas:** Подтвердить сквозную доставку штриха учителя в контур ученика через `board_stroke` и действие «Показать здесь».

Все поставленные цели Sprint 1.2 выполнены в полном объеме. Все 15 автоматизированных тестов верификационного набора (`POCKET-QA-01..15`) успешно пройдены со 100% результатом на desktop и mobile-эмуляциях.

## 2. Архитектурный анализ и исправление геометрии Code Focus

### 2.1 Корневая причина ограничения высоты (Portrait) и ширины (Landscape)
В ходе глубокого аудита CSS было обнаружено, что файл `static/css/lesson-os-v2.css` содержал жесткие правила с `!important`:
- **Строка 1251:** `.room-lesson-os #code-window.lesson-os-code-window { inset: 120px auto auto 8px !important; height: min(480px, 58vh) !important; width: calc(100% - 16px) !important; }` — принудительно ограничивала высоту 480 пикселями.
- **Строка 1230:** `.room-lesson-os #code-window.lesson-os-code-window { inset: 125px auto auto 2.5% !important; width: 52% !important; height: min(460px, 55vh) !important; }` — принудительно сжимала окно до 52% ширины в landscape.
- **Специфичность селекторов:** Класс `.room-lesson-os` находился не на теге `body`, а на внутреннем контейнере `#trainer-arena-view`. Селекторы `body.pocket-os-active.room-lesson-os` не применялись, уступая десктопным правилам.

### 2.2 Решение
В файле `static/css/boostudy-pocket-os.css` были внедрены высокоспецифичные селекторы `(0, 1, 3, 1)` с пробелом:
```css
body.pocket-os-active .room-lesson-os #code-window.lesson-os-code-window,
body.pocket-os-active .room-lesson-os #canvas-window.lesson-os-desktop,
body.pocket-os-active .room-lesson-os #task-window {
  position: absolute !important;
  display: flex !important;
  flex-direction: column !important;
  margin: 0 !important;
  border-radius: 0 !important;
  border: none !important;
  box-shadow: none !important;
}

/* Portrait (<= 768px): Занимает 100% высоты под мобильным хэдером */
body.pocket-os-active[data-pocket-focus="code"] .room-lesson-os #code-window.lesson-os-code-window {
  inset: 48px 0 0 0 !important;
  width: 100% !important;
  height: calc(100% - 48px) !important;
  z-index: 50 !important;
}

/* Landscape: Занимает 100% ширины и 100% доступной высоты под компактным хэдером */
@media (orientation: landscape) and (max-height: 500px) {
  body.pocket-os-active[data-pocket-focus="code"] .room-lesson-os #code-window.lesson-os-code-window {
    inset: 38px 0 0 0 !important;
    width: 100% !important;
    height: calc(100% - 38px) !important;
    z-index: 50 !important;
  }
}
```

### 2.3 Верифицированные метрики геометрии:
| Ориентация | Viewport | Высота окна кода | Ширина окна кода | Отступ top | Статус |
|---|---|---|---|---|---|
| **Portrait (iPhone 14)** | 390 × 844 | **740px** (было 480px) | **390px** (100%) | 48px | **PASS (POCKET-QA-03)** |
| **Landscape** | 844 × 390 | **308px** (было 280px) | **844px** (было 440px / 52%) | 38px | **PASS (POCKET-QA-04)** |

## 3. Изоляция слоя представления и сохранение десктопного WindowManager

### 3.1 Защита от глобального сброса инлайн-стилей
Десктопный WindowManager хранит геометрию каждого окна в inline-стилях (`style="top: ...; left: ...; width: ...; height: ..."`).
В Sprint 1.2:
1. Создан механизм `isolatePresentationLayer()`: перед активацией мобильного режима текущие инлайн-стили окон сериализуются в `element.dataset.pocketSavedStyle`.
2. При деактивации Pocket OS или возврате к десктопному виду функция `restoreDesktopLayer()` восстанавливает исходные инлайн-стили в неизменном виде.
3. В методе `ensureRoomWindowAccessible(windowEl)` добавлена проверка:
   ```javascript
   if (document.body.classList.contains("pocket-os-active")) return;
   ```
   Это гарантирует, что десктопный цикл нормализации окон не вмешивается в мобильный Pocket OS, а для преподавателя на десктопе поведение WindowManager сохраняется на 100%.

## 4. Детекция мобильного экрана и Fail-Closed Role Guard

1. **Fail-Closed Role Guard:** Преподаватель **ни при каких условиях** не переводится в мобильный Pocket OS, даже если в строке адреса передан флаг `?pocket_os=1` или открыто мобильное разрешение экрана:
   ```javascript
   const isTeacher = state.role === "teacher" || trainerOsConfig.is_studio_teacher;
   if (isTeacher) {
     return; // Преподаватель всегда работает в полнофункциональной Lesson OS
   }
   ```
2. **Устойчивость к повороту экрана:** Проверка мобильного устройства использует инвариант поворота:
   ```javascript
   const minScreenDim = Math.min(window.screen.width, window.screen.height);
   const isMobileScreen = minScreenDim <= 768 || (hasTouch && minScreenDim <= 1024);
   ```
   При перевороте устройства из portrait в landscape статус мобильного устройства сохраняется и не вызывает сброса состояния.

## 5. Реальное исполнение Python в Skulpt и Stale Indicator

### 5.1 Честное вычисление формул
Редактор кода подключен к существующему движку запуска `executeRunCode({ code, fileName, runId, pageId })`:
- Программа 1: `solve(20, 22)` вычисляет сумму $20 + 22$ и честно выводит `Результат: 42`.
- Программа 2: `combinations(4)` вычисляет число сочетаний $\frac{4 \cdot 3}{2} = 6$ и честно выводит `Комбинаций: 6`.
- Код возврата: `[Программа завершена с кодом 0]`.

### 5.2 Индикатор устаревшего вывода `(код изменён)`
При запуске кода система сохраняет хэш/текст в `this.lastRunCode`.
Любое изменение исходного кода в редакторе:
- Ручной ввод символов в `<textarea id="code-editor-textarea">`
- Вставка из виртуальной символьной панели (`:`, `(`, `)`, `=`, etc.)
- Прием удаленного OT-патча

немедленно отображает желтый бейдж `.pocket-terminal-stale-badge` с текстом `(код изменён)` рядом со статусом консоли. При повторном нажатии `[Запустить]` бейдж автоматически скрывается.

### 5.3 Виртуальная символьная клавиатура без Layout Shift
В обработчике нажатия клавиш виртуальной клавиатуры применен `e.preventDefault()` на событии `pointerdown`. Это предотвращает потерю фокуса текстовым полем и исключает прыжки разметки и скрытие экранной клавиатуры при вставке служебных знаков.

## 7. Двусторонняя синхронизация BooCanvas и Show Here

### 7.1 Сквозная доставка штрихов (`board_stroke`)
1. Преподаватель рисует штрих на десктопной доске в области мобильного контура.
2. Событие `board_stroke` передается через Socket.IO на сервер и рассылается в комнату урока.
3. Мобильный клиент ученика принимает штрих и вызывает `window.BooCanvasOverlay.applyRemoteStrokeCommit(stroke)`.
4. Количество объектов в коллекции `BooCanvasOverlay.getStrokes()` инкрементируется, и штрих мгновенно отображается на мобильном холсте.

### 7.2 Команда «Показать здесь» (`whiteboard_show_here`)
1. Преподаватель нажимает кнопку «Показать здесь» в контекстном меню мобильного контура.
2. Клиент передает мировые координаты области `(world_x, world_y, world_w, world_h)`.
3. Мобильный клиент автоматически центрирует и масштабирует холст через `setCamera()`, точно обрамляя область внимания учителя.
