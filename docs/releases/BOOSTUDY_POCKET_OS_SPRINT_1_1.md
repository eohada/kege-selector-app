## 1. Причина сбоя визуальной приёмки Sprint 1 и корневые причины тёмной темы

В Sprint 1 была успешно заложена архитектурная основа: трехфокусная модель навигации без потери DOM-состояния, синхронизация через Socket.IO, LiveKit WebRTC, контур ученика на десктопе преподавателя и жесты multi-touch. Однако визуальная приемка владельца продукта была отклонена со следующей формулировкой:

> *"Архитектура принята в принципе. Визуальная и UX-приемка провалена: разработана почти полностью тёмная мобильная оболочка при том, что BooStudy — светлая образовательная платформа. В результате Pocket OS выглядит как сторонний технический продукт. Дополнительно обнаружены: наложения плавающего видео на элементы управления доски, дублирование тулбаров, технический вид консоли и нехватка контекстных действий на десктопном контуре преподавателя."*

### Анализ корневых причин:
1. **Дефолтные стили Slate/Dark:** В первоначальной CSS-реализации использовались утилитарные цвета `slate-900` (`#0f172a`), `slate-800` (`#1e293b`), монохромные темные панели и темный редактор кода, что противоречит фирменному стилю BooStudy.
2. **Перекрытие окон непрозрачными поверхностями:** Поверхность `#pocket-focus-surface` имела непрозрачный фон `background: var(--pocket-bg);` и высокий `z-index: 150`, из-за чего нижележащие окна (#code-window, #task-window) иногда перекрывались пустым белым слоем.
3. **Конфликт WindowManager desktop/mobile:** При переключении фокусов десктопный WindowManager проставлял инлайновые стили `opacity: 0` при минимизации, что требовало явного сброса прозрачности и видимости.
4. **Фиксированное позиционирование LiveKit:** Плавающая плашка LiveKit имела единые абсолютные координаты, из-за чего в режиме доски она накладывалась на зум-кнопки в правом нижнем углу, а в режиме кода — на кнопки запуска.
5. **Отсутствие микро-контекста на десктопе:** Преподаватель видел мобильный контур, но для фокусировки или отправки подсказок ему приходилось искать действия в глобальных тулбарах.

В Sprint 1.1 была проведена полная переработка интерфейса на основе аутентичной светлой дизайн-системы **BooStudy Light**.

## 4. Новая композиция фокусов: BOARD, CODE, TASK

### 4.1 BOARD Focus (Интерактивная светлая доска)
- **Фон и сетка:** Светлый холст с точечной сеткой BooStudy.
- **Статус доступа:** Бейдж в левом верхнем углу `[🔒 Только просмотр]` на белой подложке с фиолетовой рамкой, предотвращающий случайные штрихи пальцами.
- **Эргономика управления:**
  - Зум-контролы `[+]` и `[-]` сгруппированы в правом нижнем углу (`bottom: 16px; right: 14px;`).
  - Видео-плашка LiveKit автоматически прижата к правому верхнему углу (`top: 14px; right: 14px;`), полностью исключая пересечения с зум-кнопками.
  - Поддержка multi-touch pinch-to-zoom и плавного панорамирования одним пальцем.

### 4.2 CODE Focus (Чистый редактор и светлая консоль)
- **Единый заголовок редактора:**
  - Имя файла `main.py` со светлым тегом языка `PYTHON`.
  - Зеленый индикатор автосохранения `● Сохранено`.
  - Кнопка `[Консоль]` для быстрого открытия/закрытия вывода.
  - Яркая фиолетовая кнопка `[Запустить]` (`#5b35f5`) с белой стрелкой `ph-play`.
- **Светлый редактор кода:**
  - Белый фон редактора (`#ffffff`) с контрастной серой полосой номеров строк (`#f8fafc`, рамка `#e2e8f0`).
  - Подсветка синтаксиса Python в стиле BooStudy Light: ключевые слова (`def`, `return`) — глубокий фиолетовый `#7c3aed`, функции — синий `#2563eb`, числа — янтарный `#d97706`, строки — изумрудный `#059669`.
- **Виртуальная символьная клавиатура (`.pocket-symbol-strip`):**
  - Горизонтальная лента быстрых символов: `Tab`, `(`, `)`, `[`, `]`, `{`, `}`, `:`, `=`, `"`, `'`, `_`, `+`, `-`, `*`, `/`, `%`.
  - Вставка в позицию курсора без потери фокуса ввода.
- **Светлая выдвижная консоль (`#pocket-terminal-drawer`):**
  - Полноценная светлая панель снизу с белым фоном, мягкой границей и тенью.
  - Заголовок с моноширинной иконкой `>_ Консоль`, кнопка `[Очистить]` и кнопка закрытия `[▾]`.
  - Вывод исполнения моноширинным шрифтом на светло-серой подложке `#f8fafc`.

### 4.3 TASK Focus (Задание и Empty State)
- **Пустое состояние (Empty State):**
  - Если преподаватель еще не выдал активное задание, ученик видит вежливую карточку с иллюстрацией-сквирклом, заголовком *"Задание пока не выбрано"* и пояснением *"Преподаватель скоро откроет задачу на уроке. Пока вы можете изучать доску или писать код."*.
  - Две быстрые кнопки навигации: `[Перейти к доске]` и `[В редактор кода]`.
- **Активное состояние задачи:**
  - Светлая карточка условия с номером задания, темой (например, `Алгоритмы на графах`) и полным форматированным текстом условия задачи.
  - Карточка ответа со строкой ввода и кнопкой `[Сдать ответ]`.
  - Скрыты инструменты редактирования и создания задач для учителя.

## 5. Изменения в нотификациях и подсказках фокуса

Вместо принудительного захвата интерфейса ученика реализована деликатная контекстная подсказка (Focus Suggestion Toast):
- При отправке преподавателем подсказки фокуса (`board`, `code`, `task`) в верхней части мобильного экрана появляется всплывающая плашка `#pocket-toast`.
- **Дизайн карточки:** Белая скругленная плашка с фиолетовой иконкой лампочки `ph-lightbulb`, четким текстом предложения (например, *"Преподаватель предлагает перейти в редактор кода"*), фиолетовой кнопкой `[В код]` и кнопкой отклонения `[✕]`.
- **Недеструктивность:** Ученик может в один клик принять предложение либо закрыть его, не прерывая текущее действие.

## 6. LiveKit: размещение, компактность, жизненный цикл видео

Плавающая видео-плашка LiveKit (`#pocket-video-pill`) оптимизирована для мобильного урока:
1. **Компактный размер:** Уменьшена до эргономичных 72×96px (16:9 вертикальный формат) с радиусом скругления 12px, белой рамкой и плавающей тенью.
2. **Динамическое позиционирование без пересечений:**
   - В фокусе **BOARD:** `top: 14px; right: 14px; bottom: auto;` (свободный правый верхний угол, вдали от зум-контролов).
   - В фокусе **CODE:** `bottom: 56px; right: 14px; top: auto;` (над полосой символов, не перекрывая кнопки запуска в шапке).
   - В фокусе **TASK:** `bottom: 16px; right: 14px; top: auto;` (над нижним баром, не перекрывая текст задания).
3. **Непрерывность соединения:** Плашка привязана к корневой оболочке Pocket OS. При переключении фокусов WebRTC-поток не пересоздается, видео и аудио не прерываются.

## 7. Управление преподавателя на десктопе: контекстное меню на контуре

На десктопной доске преподавателя мобильный ученик отображается фиолетовым штриховым прямоугольником (`.board-student-viewport-box.is-mobile-contour`).
На контуре размещен компактный контекстный бейдж с быстрыми действиями:
1. **Индикация устройства:** Иконка смартфона + тег `Pocket` + имя ученика.
2. **Кнопка `[К контуру]` (`ph-crosshair`):** Мгновенно центрирует камеру преподавателя на области видимости ученика.
3. **Кнопка `[Показать здесь]` (`ph-broadcast`):** Передает текущую область доски преподавателя на экран ученика с плавной анимацией масштабирования.
4. **Выпадающее меню `[Фокус ▾]` (`ph-lightbulb`):**
   - Позволяет в один клик предложить ученику переключиться: `Доска`, `Код`, `Задание`.
   - Не загромождает экран и открывается только по клику преподавателя.

## 13. Инструкция для локального запуска и проверки

### 1. Переменные окружения (.env)
Убедитесь, что в файле `.env` установлен флаг:
```env
BOOSTUDY_POCKET_OS_ENABLED=true
```

### 2. Запуск локального сервера
```bash
python -u scripts/run_local.py
```
Сервер будет доступен по адресу `http://127.0.0.1:5000`.

### 3. Авторизация и открытие урока
- **Окно ученика (Мобильный вид):**
  - Открыть в Chrome DevTools (режим эмуляции iPhone 14, 390×844).
  - Войти как `qa_pool_student_1` / `123456`.
  - Перейти по ссылке: `http://127.0.0.1:5000/lesson/2168/room?pocket_os=1`.
- **Окно преподавателя (Десктоп 1920×1080):**
  - Войти как `qa_pool_tutor_1` / `123456`.
  - Перейти по ссылке: `http://127.0.0.1:5000/lesson/2168/room`.
  - Наблюдать фиолетовый мобильный контур ученика с действиями `[К контуру]`, `[Показать здесь]` и меню `[Фокус ▾]`.

### 4. Запуск автоматических тестов
```bash
# Контрактные тесты
DATABASE_URL=sqlite:///:memory: BOOSTUDY_SKIP_DATABASE_BOOTSTRAP=1 BOOSTUDY_BACKGROUND_WORKERS_ENABLED=0 ./venv/bin/pytest tests/v2/test_pocket_os_contract.py

# Сквозные Playwright E2E тесты
BOOSTUDY_E2E_SKIP_SERVER=1 npx playwright test tests/e2e/test_pocket_os_mobile_lesson.spec.ts --project=desktop-chromium
```
