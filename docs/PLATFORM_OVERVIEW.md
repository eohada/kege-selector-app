Документ объединяет:
1. Функции для ученика и процесс взаимодействия.
2. Описание платформы в целом и зоны адаптации под ОГЭ.

# Часть 1. Ученик: функции и взаимодействие

## 1.1. Вход и первая точка входа

- **Регистрация по приглашению** — ученик переходит по ссылке `/invite/<token>`, вводит логин и пароль. Роль по умолчанию — `student`; при создании приглашения можно указать `student_id` для привязки к карточке ученика.
- **После входа** — пользователь с ролью `student` перенаправляется на **дашборд ученика** (`/student/dashboard`), а не на общий дашборд со списком учеников.
- **Профиль ученика** — ученик имеет доступ только к своему профилю: при попытке открыть чужой `student_id` происходит редирект на свой профиль.

## 1.2. Права доступа ученика (RBAC)

У роли `student` заданы разрешения:

| Разрешение | Описание |
|------------|----------|
| `plan.view` | Просмотр учебного плана/траектории |
| `gradebook.view` | Просмотр журнала оценок |
| `assignment.view` | Просмотр и выполнение назначенных работ |
| `schedule.view` | Просмотр расписания |
| `diagnostics.view` | Просмотр диагностики (слабые темы, контрольные точки) |
| `trainer.use` | Доступ к тренажёру |
| `theory.view` | Просмотр теории по заданиям ЕГЭ |

Редактирование плана, журнала, создание уроков/работ, проверка заданий ученику недоступны.

## 1.3. Функции, доступные ученику

### Дашборд ученика (`/student/dashboard`)

- Заголовок «Дашборд», имя ученика.
- **Уведомления** — ссылка на список с счётчиком непрочитанных.
- **Аналитика** — переход к единой странице статистики/аналитики ученика.
- **Траектория (план)** — ближайшие пункты учебного плана (до 12), статусы, дедлайны, ссылка «Открыть» на полный план.
- **Активные работы** — назначенные работы (ASSIGNED / IN_PROGRESS / RETURNED), до 12 штук; переход к выполнению по клику.
- **Слабые темы** — темы с процентом успешности ниже порога (из диагностики).
- **Последние оценки** — недавние записи журнала оценок.

Если у пользователя нет привязанной записи ученика, дашборд показывается с сообщением «Профиль ученика не найден» и пустыми блоками.

### Профиль ученика (`/student/<student_id>`)

Ученик попадает сюда по ссылке из дашборда или после редиректа с главной. Видит только свой профиль.

- Карточка ученика: имя, подписка (если есть), преподаватели, родители (для ученика не показываются).
- **Активные сдачи (Submission)** — назначенные работы со статусами и ссылками на выполнение.
- **Уроки** — лента своих уроков (последний завершённый, текущий, ближайшие, остальные). Для урока доступны ссылки на классную работу, домашнюю/проверочную через раздел «Задания».

### Учебный план / траектория (`/student/<student_id>/plan`)

- Только просмотр списка пунктов плана (статусы: planned, in_progress, done, failed), дедлайны, приоритеты.
- Добавлять, редактировать и удалять пункты ученик не может.

### Журнал оценок (`/student/<student_id>/gradebook`)

- Просмотр записей журнала. Экспорт в CSV и PDF (при наличии права `gradebook.view`).
- Редактирование записей недоступно.

### Диагностика (`/student/<student_id>/diagnostics`)

- Сводные метрики, проблемные темы, проблемные номера заданий.
- Сохранённые контрольные точки (baseline/checkpoint) — только просмотр. Сохранять новые контрольные точки ученик не может.

### Аналитика / статистика (`/student/<student_id>/analytics`)

- Единая страница с табами: тренд GPA, карта навыков, посещаемость, пунктуальность сдачи, статистика по номерам заданий и т.п.
- Режим только просмотра.

### Расписание (`/schedule/...`)

- Ученик видит расписание в рамках своей области видимости (только свои уроки). Режим просмотра.

### Задания (Assignment / Submission)

- **Список работ** (`/submissions`) — все назначенные ученику работы и «рабочие пространства» по урокам.
- **Открытие работы** (`/submissions/<submission_id>`) — просмотр заданий, таймер (если включён лимит времени), дедлайн, лимиты попыток.
- **Старт работы** — POST `/submissions/<id>/start`: переход из ASSIGNED в IN_PROGRESS.
- **Сдача ответов** — отправка ответов по задачам в рамках лимитов попыток и дедлайна.

### Уроки (классная комната)

- **Просмотр классной работы** (`/lesson/<lesson_id>/classwork-tasks`) — список заданий классной работы, материалы урока.
- **Режим ученика:** при включённой сдаче заданий ученик может сохранять черновики и сдавать ответы (все разом или по одному заданию). После сдачи — просмотр статусов (submitted/graded/returned), итогов проверки и комментариев преподавателя.

### Тренажёр (`/trainer`, `/trainer/v2`)

- Доступ при наличии права `trainer.use` и при включённом `allow_trainer` в тарифе.
- Ученик может: получать задания, запрашивать подсказки, отправлять ответы, запускать код, смотреть рекомендации и статистику по задачам.

### Теория (`/theory`, `/theory/<task_number>`)

- Просмотр списка теоретических блоков и теории по номеру задания ЕГЭ. Только чтение.

### Уведомления (`/notifications`)

- Список уведомлений, отметка прочитанных. Счётчик непрочитанных на дашборде.

### Режим урока и «начать урок»

- **Режим урока** (`/student/<student_id>/lesson-mode`) — страница с текущим и ближайшим уроком.
- **Начать урок** — POST `student_start_lesson`: ближайший запланированный урок переводится в in_progress или создаётся новый урок. После этого ученик переходит в классную комнату.

## 1.4. Типовой сценарий взаимодействия ученика

1. Вход по приглашению или логин → редирект на `/student/dashboard`.
2. Дашборд: обзор плана, активных работ, слабых тем, оценок; переход в «Все» работы или в конкретную сдачу.
3. Работы: `/submissions` → выбор работы → при необходимости «Старт» → ввод ответов → сдача.
4. Уроки: из профиля или расписания → классная комната → решение заданий → сохранение черновика или сдача.
5. План и прогресс: план, журнал, диагностика, аналитика — только просмотр.
6. Самоподготовка: тренажёр и теория.
7. Уведомления — просмотр и переход по ссылкам к уроку или сдаче.

## 1.5. Чего ученик не может делать

- Создавать/редактировать/удалять уроки, задания, пункты плана, записи журнала, контрольные точки диагностики.
- Менять статистику, проверять работы других, пользоваться журналом проверок.
- Видеть чужих учеников и чужие сдачи/уроки.
- Управлять теорией, тренажёром, приглашениями, подпиской.

# Часть 2. Платформа в целом и адаптация под ОГЭ

## 2.1. Назначение и стек

- **Назначение:** платформа для подготовки к экзаменам (сейчас заточена под **ЕГЭ по информатике** — КЕГЭ): уроки, задания, тренажёр, теория, аналитика, расписание, биллинг.
- **Бэкенд:** Flask (Python), SQLAlchemy, PostgreSQL (прод) / SQLite (локально).
- **Фронт:** серверный рендер (Jinja2), статика (CSS/JS), Socket.IO для комнаты урока.
- **Дополнительно:** отдельное приложение тренажёра (trainer_app), парсер заданий (scraper), телеграм-бот, удалённый админ (remote_admin).

## 2.2. Роли и модули (blueprints)

| Модуль | Назначение |
|--------|------------|
| **auth** | Вход, профиль, подписка (allow_lessons / allow_trainer). |
| **main** | Landing, dashboard, редиректы по ролям, дашборд ученика, экспорт/импорт. |
| **students** | Профиль ученика, план, журнал, диагностика, аналитика, создание/архив учеников. |
| **lessons** | Уроки, классная комната (ДЗ/КР/проверочная), проверка, диалоги, доска. |
| **assignments** | Работы (Assignment), сдачи (Submission), ответы, таймер, лимиты попыток. |
| **schedule** | Расписание, повторяющиеся слоты, создание уроков из расписания. |
| **trainer** | Тренажёр (iframe/v2), токены, API подсказок/задач/запуска кода. |
| **theory** | Теория по «номерам заданий» (сейчас 1–27 ЕГЭ). |
| **kege_generator** | Выбор заданий по типу (task_number), привязка к уроку, шаблоны. |
| **courses** | Курсы и модули (траектория). |
| **groups** | Группы учеников. |
| **billing** | Тарифы, подписки (в т.ч. allow_lessons / allow_trainer). |
| **notifications** | Уведомления пользователю. |
| **onboarding** | Приглашения (роль student, привязка к ученику). |
| **parents** | Дашборд родителя, привязка к детям. |
| **admin / remote_admin** | Пользователи, роли, семья, окружение. |
| **rubrics** | Критерии проверки. |
| **designer / library / uploads** | Ресурсы, загрузки. |
| **api** | Внешний API. |
| **qa** | Внутренние задачи QA. |

Роли: creator, admin, tutor, **student**, parent, designer, tester, content_maker. У ученика в карточке уже есть **категория: ЕГЭ / ОГЭ / ЛЕВЕЛАП / ПРОГРАММИРОВАНИЕ** — единственное явное «место» под ОГЭ в текущей модели.

## 2.3. Модель данных (кратко)

- **Users / UserProfile** — пользователи, роли, профиль.
- **Students** — карточка ученика: `category` (ЕГЭ/ОГЭ/…), цель, класс, подписка через user_id.
- **Lesson / LessonTask** — уроки, задачи урока (ДЗ/КР/проверочная), ответы, статусы проверки.
- **Assignment / AssignmentTask / Submission / Answer** — отдельные «работы» с дедлайном, таймером, попытками.
- **Tasks** — банк заданий: `task_id`, **task_number** (целое число), контент, ответ, сложность, подсказки, привязка к Topic и KnowledgeNode. **Тип экзамена (ЕГЭ/ОГЭ) в таблице не хранится.**
- **Topic** — темы (навыки), связь с заданиями через `task_topics`.
- **TheoryBlock** — теория по **одному номеру задания**; поле **task_number (1–27)** и уникальность по нему — явная привязка к ЕГЭ.
- **StudentTheoryAccess** — доступ ученика к теории по **task_number**.
- **Subject / KnowledgeNode / UserMastery / AnalyticsEvent** — граф знаний и аналитика (прогноз балла ЕГЭ, Elo и т.д.).
- **StudentTaskStatistics** — ручная статистика по ученику по **task_number** (без указания экзамена).
- **TariffPlan / UserSubscription** — тарифы и подписки.

Сейчас вся логика «типа задания» завязана на **одно число — task_number**. Для ЕГЭ по информатике это 1–27; для ОГЭ нужна либо вторая ось (тип экзамена), либо отдельный диапазон номеров.

## 2.4. Контент и контент-процессы

- **Банк заданий (Tasks):** парсинг (scraper), прототипы в `data/reference_prototypes/task_XX/` (номера 1–27), сложность, подсказки, эталонные решения.
- **Тренажёр:** `trainer_knowledge/tasks/by_number/` — файлы по номерам 1–27 и по `task_id`.
- **Теория:** блоки по номеру задания 1–27; в коде задано `THEORY_TASK_NUMBERS = list(range(1, 28))`.
- **КЕГЭ-генератор:** выбор «типа» = выбор **task_number** (1–27), добавление заданий в урок/работу.
- **Селектор заданий** (`core/selector_logic.py`): выбор задач по **task_type** (= task_number), без учёта экзамена.

## 2.5. Где зашит «ЕГЭ» и номера 1–27

| Место | Что сделано под ЕГЭ |
|-------|---------------------|
| **Student.category** | Выбор «ЕГЭ» / «ОГЭ» / «ЛЕВЕЛАП» / «ПРОГРАММИРОВАНИЕ» — уже есть. |
| **Tasks** | Только `task_number`, экзамен не хранится. |
| **TheoryBlock** | `task_number` 1–27, уникальный на номер. |
| **theory/routes.py** | `THEORY_TASK_NUMBERS = list(range(1, 28))`, проверка `task_number in THEORY_TASK_NUMBERS`. |
| **StudentTheoryAccess** | `task_number` в комментариях «1–27». |
| **kege_generator** | Выбор «Задание 1»…«Задание 27», при пустой БД — `range(1, 28)`. |
| **selector_logic** | Фильтр по `Tasks.task_number == task_type`; один общий банк. |
| **StatsService / аналитика** | Статистика по задачам; явной привязки к «ЕГЭ» в коде мало, но номера подразумевают один экзамен. |
| **Analytics engine** | Прогноз балла ЕГЭ, Elo по узлам знаний. |
| **trainer_knowledge** | Файлы по номерам 1–27. |
| **data/reference_prototypes** | Каталоги task_01 … task_27. |
| **Topic** | Универсальные темы — доработка под ОГЭ минимальна. |

Итого: платформа по сути «одна линейка заданий 1–27» без явного разделения ЕГЭ/ОГЭ. Чтобы поддерживать ОГЭ, нужно ввести разделение по типу экзамена и протащить его по контенту и логике.

## 2.6. С чем предстоит работать при адаптации под ОГЭ

### Модель данных и идентификация заданий

- **Tasks:** ввести признак экзамена (например `exam_type`: `'ege'` / `'oge'`) или привязку к Subject. Номера заданий ОГЭ свои — либо отдельный диапазон, либо один `task_number` в связке с `exam_type`.
- **TheoryBlock:** сейчас один блок на номер (1–27). Для ОГЭ: либо отдельная таблица/поле `exam_type`, либо свои номера (например 1–15 для ОГЭ) и обобщение «теория по (exam_type, task_number)».
- **StudentTheoryAccess:** то же — учитывать экзамен при проверке доступа.
- **StudentTaskStatistics:** при необходимости развести статистику ЕГЭ/ОГЭ — добавить exam_type.

### Контент

- Заполнить банк заданий ОГЭ (парсер/импорт, свои номера или exam_type=oge).
- Эталоны и прототипы: аналог `data/reference_prototypes/` для ОГЭ.
- Тренажёр: `trainer_knowledge` — либо подпапки по экзамену, либо префикс в имени (например `oge/by_number/`).
- Теория: контент по заданиям ОГЭ и привязка к (exam_type, task_number) или к отдельным номерам ОГЭ.

### Логика выбора и отображения заданий

- **selector_logic:** фильтр не только по `task_number`, но и по типу экзамена (или по subject_id).
- **kege_generator:** выбор экзамена (ЕГЭ/ОГЭ) и типа задания в зависимости от выбранного экзамена.
- **assignments / lessons:** при создании работ и уроков — откуда брать список «типов заданий» в зависимости от ученика/урока (например по Student.category).

### Теория

- **theory/routes.py:** убрать жёсткое `THEORY_TASK_NUMBERS = list(range(1, 28))`; брать список номеров из конфига/БД по экзамену.
- **TheoryBlock:** уникальность и выборка по (exam_type, task_number) или отдельные номера для ОГЭ.

### Аналитика и диагностика

- **StatsService / диагностика:** при отображении «по номерам заданий» учитывать экзамен. Либо раздельные блоки/вкладки «ЕГЭ» / «ОГЭ».
- **Analytics engine (прогноз балла):** для ОГЭ — отдельная шкала и при необходимости отдельный граф/Subject.

### UI и сценарии

- Дашборд и профиль ученика: при category=ОГЭ показывать контент/задания/теорию/тренажёр для ОГЭ.
- Фильтры списка учеников по категории (ЕГЭ/ОГЭ) уже есть.

### Тренажёр (trainer_app)

- Получение заданий и подсказок по типу экзамена (и номеру задания в рамках этого типа).
- Внутренний API при необходимости передаёт exam_type или список номеров в зависимости от контекста.

## 2.7. Что уже готово под «разделение»

- **Student.category** — ЕГЭ / ОГЭ / ЛЕВЕЛАП / ПРОГРАММИРОВАНИЕ: можно использовать для фильтрации и выбора контента под ОГЭ.
- **Topic** — общие темы, подойдут для обоих экзаменов при правильной разметке заданий.
- **Subject / KnowledgeNode** — можно завести отдельный Subject для ОГЭ и привязать к нему узлы и задания.
- Остальная инфраструктура (уроки, сдачи, журнал, расписание, биллинг, роли) не привязана к типу экзамена и может обслуживать и ЕГЭ, и ОГЭ после введения разделения на уровне заданий и теории.

## 2.8. Краткий чеклист для адаптации под ОГЭ

1. **Данные:** ввести разделение заданий по экзамену (exam_type / subject) в Tasks; при необходимости — в TheoryBlock и StudentTheoryAccess.
2. **Контент:** банк заданий ОГЭ, прототипы, trainer_knowledge, теория по заданиям ОГЭ.
3. **Селектор и генератор:** фильтр и выбор типов заданий с учётом экзамена (и при необходимости привязка к Student.category).
4. **Теория:** обобщить номера заданий (конфиг/БД по экзамену), изменить уникальность и выборки.
5. **Аналитика/диагностика:** разделение отчётов и прогноза по экзамену.
6. **Тренажёр:** выдача заданий и подсказок с учётом типа экзамена.
7. **UI:** везде, где показываются «задание N» или теория — учитывать контекст ЕГЭ/ОГЭ (ученик, урок, работа).
