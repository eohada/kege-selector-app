### 2.3. Доказательство отсутствия дедлоков (Lock Ordering)
Все операции модификации расписания (`create_lesson`, `reschedule`, `update_lesson`) используют единый атомарный вход через `acquire_scheduling_locks`:
1. `SELECT ... FROM "Students" WHERE student_id = ? FOR UPDATE`
2. `SELECT ... FROM "Users" WHERE id = ? FOR UPDATE`

Поскольку порядок блокировок строго глобален (`Student` всегда предшествует `User`), возникновение циклических ожиданий (граф типа $A \rightarrow B \rightarrow A$) алгоритмически невозможно.

- **390x844 (Mobile Phone):** Одноколоночный вид расписания с удобными табами дней недели.

### 4.2. Соответствие BooStudy UI Canon

- **Пилл-табы:** Переключатели «Неделя» / «Месяц» выполнены на pill-кнопках с акцентным цветом Indigo-600.
- **Состояния уроков:** Цветовое кодирование: Planned — Indigo/Blue, In Progress — Emerald/Green, Cancelled — Slate/Rose, Completed — Emerald/Purple.

### 4.3. Баг-репорт: Устранение падения Month View
- **Дефект:** При запросе `GET /schedule?view=month` сервер падал с кодом 500 (`IndexError: list index out of range`).
- **Причина:** В коде `app/schedule/routes.py` для вычисления недельных метрик напрямую читались индексы `week_start_date = week_days[0]` и `week_end_date = week_days[-1]`, тогда как при `view_mode == 'month'` массив `week_days` инициализировался пустым (`[]`).
- **Исправление:** В строках 954-955 добавлена безопасная альтернатива:
  ```python
  week_start_date = week_days[0] if week_days else period_start
  week_end_date = week_days[-1] if week_days else period_end
  ```
- **Верификация:** Месячный вид открывается без ошибок, скриншот `07_month_view_multiple_lessons.png` успешно сохранён.

## 5. Security, Legacy & RBAC Audit (Этап 4)

### 5.1. Инвентаризация маршрутов расписания

| Маршрут | Метод | Аутентификация / Роли | Назначение |
|---------|-------|----------------------|------------|
| `/schedule` | GET | `login_required` (tutor, student, parent, admin) | Главная страница расписания |
| `/api/schedule/create_lesson` | POST | `login_required` (tutor, admin) + CSRF | Создание урока с валидацией принадлежности |
| `/schedule/reschedule/<id>` | POST | `login_required` (owner tutor, admin) + CSRF | Перенос занятия на новую дату/время |
| `/api/schedule/update_lesson/<id>` | POST, PUT | `login_required` (owner tutor, admin) + CSRF | Обновление статуса, темы, заметок |
| `/api/schedule/lesson/<id>/details` | GET | `login_required` (owner tutor, student, admin) | Получение метаданных урока (IDOR guard) |
| `/api/schedule/delete_lesson/<id>` | POST, DELETE | `login_required` (owner tutor, admin) + CSRF | Удаление урока |
| `/api/schedule/events` | GET | `login_required` (tutor, student, admin) | JSON-поток событий для календаря |
| `/schedule/export.ics` | GET | `login_required` | Экспорт персонального iCalendar (.ics) |
| `/schedule/ics/<token>` | GET | Публичный (по криптографическому токену) | Синхронизация с Apple/Google Calendar |
| `/schedule/templates/api/*` | GET, POST | `login_required` (tutor, admin) | Шаблоны повторяющихся слотов |

### 5.2. IDOR Protection & Historical Data Guard
- Попытка Tutor A получить детали или изменить урок Tutor B блокируется с возвратом HTTP 403 Forbidden.
- Для уроков с `teacher_id IS NULL` (исторические данные): доступ разрешается только администраторам либо единственному прикреплённому преподавателю ученика. При наличии нескольких преподавателей просмотр делегируется исключительно администраторам.

## 6. Lifecycle, Action & Timezone Audit (Этап 5)

1. **Жизненный цикл урока:**
   - Переходы между состояниями `planned` $\rightarrow$ `in_progress` $\rightarrow$ `completed` $\rightarrow$ `cancelled` верифицированы.
   - Проведённые уроки (`completed`) защищены от случайного переноса и удаления.
2. **Часовые пояса:**
   - В БД (`Lessons.lesson_date`) время хранится строго в UTC.
   - В UI и API отображение динамически конвертируется в часовой пояс пользователя (`timezone_iana` или селектор в шапке).
   - Проверены смещения: UTC, Europe/Moscow (+3), Asia/Tomsk (+7). Наложение слотов рассчитывается в абсолютном времени UTC.
3. **Биллинг:**
   - Никаких списаний и балансовых девиаций при переносах уроков не происходит. Баланс списывается только при подтверждённом статусе `completed`.
